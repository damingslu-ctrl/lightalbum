# 标准化软件迭代指导书（通用 SOP）

> 定位：**与具体项目解耦**的迭代标准流程。项目相关的事实（工具链路径、QA 门、基线值）
> 放在「附录 A 项目实例」中，本文件只定义流程、门禁与产出物。
> 信条：**可重复 > 可解释 > 可优化**；先测量再优化；没实测就不许说"好了"。

---

## 1. 总则

| 项 | 约定 |
|---|---|
| 迭代单位 | 一个**可独立验收的需求条目**（一次只做一件事） |
| 完成定义 DoD | 需求有验收标准 → 实现 → 质量门禁全绿 → 文档/CHANGELOG 更新 → 可发布产物 → 提交可追溯 |
| 事实等级 | `已确认`（有日志/计数/截图）／`推测`（必须写明验证方式）——禁止混用 |
| 回退原则 | 任一门禁红 → 不发布，回到实现步；禁止"先提交以后再修" |

## 2. 流程（10 步）

```
1 需求条目化  2 影响面评估  3 取证  4 根因/方案  5 实施
6 质量门禁    7 文档与版本  8 发布产物  9 提交与追溯  10 复盘沉淀
```

1. **需求条目化**：一句话需求 + 验收标准（可断言）+ 优先级 + 约束（能否改数据结构/升版本）。
2. **影响面评估**：涉及哪些模块/数据/契约；**判定层与数据格式改动必须先讲后做**。
3. **取证**：日志、计数、截图、性能数字；不做没有证据的推断。
4. **方案**：主方案 + 备选 + 取舍 + 风险；标注需要用户拍板处。
5. **实施**：小步、可回退；改完立刻核验（见 §6 补丁规范）。
6. **质量门禁**（§4）：对应门全绿；**新增缺陷必须新增一条可断言用例**。
7. **文档与版本**（§5）：CHANGELOG、README/ADR、版本号单一真源。
8. **发布产物**：构建 → 打包 → 产物校验（大小/能否启动/关键路径）。
9. **提交与追溯**：提交信息 = 现象/需求 → 根因 → 改法 → 实测数据。
10. **复盘沉淀**：经验写进项目记忆；**可复用的流程沉淀为 skill**。

## 3. 版本与分支

- **SemVer**：`MAJOR.MINOR.PATCH`；新功能=MINOR，修复=PATCH，破坏性=MAJOR。
- **版本号单一真源**：只在构建定义里写一次，打包脚本从那里解析；禁止两处硬编码。
- **分支**：`main` 始终可发布；改动走短生命周期分支或直接小步提交（单人工况）。
- **CHANGELOG**：每次发布追加一条 `[版本] - 日期` + 新增/修复/变更/实测。

## 4. 质量门禁（红即停）

| 层 | 门禁 | 判据 |
|---|---|---|
| 构建 | 编译/链接 | 0 error；warning 不新增类别 |
| 结构 | 结构烟雾门 | 关键计数与基线一致（或说明差异） |
| 功能 | 交互/链路门 | 逐条断言全绿（不接受"看起来对"） |
| 视觉 | 像素门 | 分色计数 > 0 且与基线同量级 |
| 性能 | 帧耗时门 | 均值 ≤ 帧预算（如 30fps ⇒ 33ms），并记录前后对比 |
| 回归 | 全量门 | 上一版本门的值不变或差异已解释 |

- **环境可复现**：门禁命令、环境变量、期望值必须写进项目实例（附录 A）。
- **自动化优先**：能断言就不肉眼；能脚本就不手点。

## 5. 文档产出

- `CHANGELOG.md`：每次发布一条（必做）。
- `README.md`：构建/运行/目录约定（必做）。
- `docs/`：架构/ADR/模块说明（有重大决策时必做）。
- **知识沉淀**：项目记忆按日追加；跨项目习惯进用户记忆；**可复用流程沉淀为 skill**。

## 6. 补丁规范

- **先读后改**，改完用检索核验（工具存在静默不落盘）。
- **编码/换行**：脚本替换时按文件真实换行构造匹配串，并用 `assert(命中次数==期望)` 兜底。
- **不删不确认的文件**：个人目录禁止递归删除；产物用"移走"而非删除。

## 7. 通用工程铁律（跨语言/跨项目）

1. **单一真源**：常量、版本号、变换数学、缓存失效入口——都只能有一处定义/入口。
2. **绘制与命中同源**：任何"看得见 vs 点得到"的逻辑必须共用同一套变换。
3. **渲染热路径不做 O(n) 重建**：静态内容 bake/缓存，动态内容合批。
4. **复用抽象要重审守卫**：新增视图/状态时，检查所有 `if (层级/类型 == X)` 分支。
5. **边界与退化显式处理**：空集合、零尺寸、夹取值（读取夹取后的值，不要读原始值）。
6. **资源与状态**：绘制状态 save/restore；对象生命周期与信号连接成对。
7. **诚实数据**：无数据就显示"无"，不伪造、不占位编造。
8. **可观测**：关键路径留计数/日志开关，便于下次取证。

## 附录 A：项目实例 — LightAlbum native（Qt 6.8.3 / MinGW）

- 项目级细则（13 条事故铁律、工具链、8 个 QA 门与基线、离屏坑）：`native/docs/迭代指导书.md`
- 构建：`cmake --build build --target LightAlbum -j 8`（改前先杀残留 `LightAlbum.exe`）
- 打包：`powershell -ExecutionPolicy Bypass -File .\release.ps1`（版本从 `CMakeLists.txt` 解析）
- 门禁范式：`(QT_QPA_PLATFORM=offscreen LA_XXX=arg ./build/LightAlbum.exe > /tmp/x.log 2>&1 &) ; sleep 8 ; grep -a "LA_XXX" /tmp/x.log ; taskkill //F //IM LightAlbum.exe`
- 当前基线：`rings=2608 / names=2596`、`jade>0 points=5`、`provinces=34`、`LA_MAP_CLICK_QA` 十一断言、
  帧耗时 world≈2.3 / region≈0.35 / province≈0.35 / country≈0.30 ms
