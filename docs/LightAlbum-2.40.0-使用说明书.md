# 光影集 LightAlbum 2.40.0 · 使用说明书

> **定位声明**：LightAlbum（native 版）是唯一正式分发形态——一个**零云端、纯本地**的 Windows 桌面照片管理客户端。发行物为单文件压缩包 `LightAlbum-2.40.0-win64.zip`，解压即用；旧 1.x Python 打包版本已全部停发并清理。
>
> **本版能力面**：图库浏览 / 自动故事相册 / 足迹地图（轨迹+热力+按年筛选+国家省市三级下钻）/ 智能选片 / 修图实验室（双引擎 + AI 消除真引擎 + **一键增强 13 算子**）/ AI 美图 / 相册聚类 / 相似照片去重 / AI 场景分类 / 人脸识别与人物聚类（两遍精炼）/ 隐私库（全链路一致过滤）/ 中英双语 / 无障碍键盘操作 / 高 DPI 适配 / 统一动效引擎 / 设计语言 v2 地基层 / 原生导入器（含 iCloud 相册）/ RAW 与视频 / **HEIC·WebP 的 EXIF 容器抽取（2.38.0 起）**。所有处理均在你的电脑上完成，不向任何服务器发送照片或数据。
>
> **本版最重要的变化**：AI 分类与人脸识别**不再需要你自行启动任何服务**。以前要先把两个 Python 服务跑起来（占用 8766 / 8767 端口）才能用的功能，现在由**随包的本地引擎子进程**直接完成——程序不再监听、也不再连接任何本地端口做推理。
>
> 为此发布包内**随附五组第三方运行时与模型**（均为独立进程调用或直接读盘的数据文件，不与本程序链接）：
> LibRaw（约 3.5 MB，LGPL/CDDL 双许可）、FFmpeg（约 200 MB，GPL-3.0，仅取抽帧与读元数据能力）、
> **AI 消除执行器**（inpaint.exe + ONNX Runtime + LaMa 模型）、
> **人脸引擎**（faceinfer.exe + SCRFD 检测 / ArcFace 识别两个 ONNX 模型）、
> **场景分类引擎**（clipinfer.exe + CLIP ViT-B/32 视觉塔 + 8 类提示词矩阵）。
>
> 三组 AI 载荷的**未压缩实测体积**（可从包内 `MANIFEST.txt` 逐文件复核）：
> `3rdparty/lama/bin` 219,953,151 B（209.8 MiB）、`3rdparty/face/bin` 203,719,631 B（194.3 MiB）、
> `3rdparty/clip/bin` 363,977,280 B（347.1 MiB）——**本版压缩包因此明显大于以往**，这是把三个模型带在机器上换「离线可用 + 零外传」的代价。压缩包的实际字节数以 `release.ps1` 产出为准，本文不给未实测的数字。
>
> 五组都是**按需降级**的——缺少对应文件时，相应功能被安静地跳过或诚实提示「引擎未就绪」，其余功能完全不受影响，绝不产生没有缩略图的空卡片或假成功。

## 1. 安装与启动

1. 解压 `LightAlbum-2.40.0-win64.zip` 到任意目录（无需安装器、无需管理员权限、无注册表写入）。
2. 双击 `LightAlbum.exe` 启动。窗口标题显示「光影集 LightAlbum 2.40.0」。
3. **AI 素材已在包内**：`3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录连同模型一起解压即可用，**无需任何下载或服务启动**。
4. **首次使用**：程序启动后自动读取默认库；若库为空，点击顶栏「导入」即可建立你自己的照片库（见第 3 节）。

### 数据存放位置（默认，可用环境变量改）

| 内容 | 默认路径 | 环境变量覆盖 |
|---|---|---|
| 照片库（SQLite） | `D:\lightalbum\library.db` | `LA_DB` |
| 缩略图缓存 | `D:\lightalbum\thumbs\` | `LA_THUMPS` |

- 这两个路径与旧 1.x 版本**完全兼容**：已有库直接被读取，缩略图缓存互相命中，无需迁移。
- 若默认盘符不存在，可用环境变量指向任意位置，例如（CMD）：
  `set LA_DB=E:\photo\library.db` 后再启动。

## 2. 主界面

左侧图标栏八区：**首页 / 足迹 / 图库 / 选片 / 修图 / 美图 / 日志 / 关于**；顶栏含标题、搜索框、导入按钮与隐私库锁；首页与足迹页顶部有 KPI 条（照片总数、足迹省份等统计）。页面切换与局部反馈动效由统一动效引擎驱动（见第 14 节）。

## 3. 导入照片（原生导入器）

点击顶栏「**导入**」下拉，两个入口：

- **导入目录**：选择任意照片根目录（子目录递归扫描；`相机原始/缓存/回收站` 等辅助目录自动跳过）。
- **导入 iCloud 相册**：自动探测本机 iCloud 照片目录（`%USERPROFILE%\Pictures\iCloud Photos\Photos` 等三个候选路径），**空目录会被拒绝**以免误报「已找到」。

扫描在后台线程进行，不卡界面；可随时取消。完成后弹出汇总（新增/已存在/跳过）。

导入器行为细节：

- 读取每张照片的 **EXIF**（拍摄时间、相机、镜头、焦距、光圈、快门、ISO、GPS 坐标、方向等）——**缺失项如实留空**，显示为 `—`，绝不编造。
- **2.38.0 起**：EXIF 抽取覆盖 **WebP**（RIFF 的 EXIF chunk）与 **HEIC**（ISOBMFF `meta/iinf/iloc` 最小解析）。这两类容器先剥出内层 TIFF 数据块，再走与 JPEG 相同的解析器；**剥不出就退回文件系统修改时间**（与「JPEG 里没有拍摄时间」时走的同一条兜底路径）。诚实边界：兜底值**只填时间、不带来源标记**——界面与库里都看不出它是 EXIF 还是 mtime，需要较真时以照片文件的修改时间为准。JPEG/PNG/TIFF 三格式行为不变。
- 自动生成缩略图，缓存键与旧版共享（同一文件不会重复生成）。
- **增量安全**：重复导入同一目录时，未变化的文件直接跳过；删除照片的评分等元数据不会被覆盖。
- 云盘占位文件（OneDrive 等）会被识别并标记，不会当作有效照片。
- RAW（2.28.0 起）解码缩略图与 EXIF；视频（2.28.0 起）入库并抽帧封面，与照片同为受支持格式。

## 4. 图库（浏览）

- 网格缩略图 + 底部**胶片条**快速切换；点击打开**灯箱**全屏查看，支持滚轮缩放（以鼠标为锚点）、拖移、适屏。
- **灯箱加载原图**：先秒出缩略图，后台渐进加载原图并淡入替换；加载失败诚实降级不黑屏。大库翻图定位走索引化路径。
- 顶栏搜索框按标题/路径过滤；支持**多选**（Ctrl/Shift）与批量工具条（★评分 / 🔒私密 / 标记待删）。
- 大库下已做**窗口化虚拟化 + 两级缩略图缓存**，数千张照片滚动依旧流畅。
- **缩略图骨架屏**：未解码卡片显示 shimmer 骨架占位，解码完成平滑替换；缺画出稳定缺失态。动画尊重系统「减少动态效果」设置。

### 4.1 自动故事相册

图库页顶部一条**故事条**，一键把照片组织成「可以讲述的瞬间」。完全在视图层聚合，**不写入照片库**——原始数据不受影响，关闭筛选即回完整图库。

- **按「地点 + 时间窗口」自动分组**：同一地点、拍摄间隔不超过阈值（默认 5 天）的连续照片归为一个故事；地点先取省市、再退回大区、最后「未知地点」兜底，绝不编造坐标归属。
- **人物圆形头像墙**：故事条左侧展示已识别人物的圆形头像，点击只看该人物照片。
- **守恒保证**：分组是纯函数计算，输入多少张输出还是多少张——任何照片都不会被悄悄丢弃（由自动化门禁断言）。
- **规模封顶**：故事条最多展示 60 个分组，保证界面永远流畅。
- **一键开关**：点击故事条开启/关闭故事筛选。

## 5. 足迹（地图）

- **零外链地图**：世界地图与多国省多边形数据编在 exe 内，离线可用。
- **三级下钻**：世界 → 国家 → 省。有 GPS 的照片按真实坐标落点。
- **离线逆地理编码**：GPS 坐标归属到国家/省份（点内多边形计算 + 城市最近邻兜底）。
- **轨迹层 / 热力层 / 按年筛选**三种足迹视图随时切换。
- 诚实原则：落在覆盖范围之外的照片**留空不猜**。

## 6. 智能选片

对照片目录做本地筛选（`选片` 页）：

- **去重**：MD5 完全重复 + 感知哈希（pHash）相似聚类；
- **质量筛选**：模糊（拉普拉斯清晰度）、曝光异常检测；RAW 只做去重与分辨率检查，不参与模糊/曝光淘汰；
- 视频与照片同入选片流程（支持视频卡片与抽帧封面）；
- **隐私一致**：标记为私密的照片**不会进入**选片与相似去重结果（锁定态、解锁态均过滤），不会被间接曝光；
- 结果分为 候选 / 废片 / 精选 三组展示（7 项 KPI），可导出归档。

## 7. 修图实验室（核心）

`修图` 页，全部处理零云端：

- **手动滑杆 12 项**：曝光 / 亮度 / 对比 / 清晰 / 自然饱和 / 饱和 / 色温 / 色调 / 锐化 / 高光 / 阴影 / 暗角；
- **16 个预设** + 「智能增强」（本地规则引擎，无外部依赖）；
- **★一键增强 · 13 算子（2.38.0 起产品化）**：影调 / 人像 / 校正三组平铺在工具区，一次点击按序执行。全程**异步**（界面显示忙碌态、不冻结），每步走现有撤销/重做通道；导出时按整条序列在全分辨率重放，不是把预览小图放大。
  - **诚实反馈**：红眼修复的命中点数、肤色占比、水平校正的角度都会如实报出；判定为「无倾斜」的校正明确提示**不改动**，不假装做了事。
- **撤销栈**：任一步可回退；
- **几何编辑**：旋转、翻转、拉直 ±10°、比例裁剪与交互裁剪；
- **画笔蒙版**：局部涂抹后色调只作用于涂抹区域；
- **对比视图**：左右分割线对比原图与修后；
- **导出副本**：预览所见即导出所得；
- **★AI 消除**：涂抹要移除的物体，本地 LaMa 模型补全背景。执行器是**独立子进程**（`inpaint.exe` + ONNX Runtime + 随包模型），零云端、崩溃只影响当次任务、自动重拉；推理在专属线程，**秒级计算期间界面完全不冻结**，可看到「处理中」状态并可取消。未随附模型时诚实提示「模型未就绪」，绝不假成功。
- **图像处理速度（2.39.0 起）**：修图引擎的高斯模糊、色调映射、中值/平滑滤波、红眼与暗角、镜头校正等热点循环改为**算子内按行/按瓦片并行**（可用 `LA_LUMEN_THREADS=1` 退回串行）。并行与串行结果**逐字节相等**（不是「差不多」，是内存逐位比对，由门禁断言），像素输出语义零变化。
- **「AI 智能体」**（可选，见第 9 节）：本地大模型读测量值给出修图方案。

## 8. AI 美图

`美图` 页为风格化预设画廊：16 种风格卡片（含缩略图预览），点选套用 + 大图 before/after + 智能增强 + 导出副本。

## 9. 接入本地 AI 智能体（可选，**唯一仍需自备的服务**）

「AI 智能体」依赖本机运行的 [Ollama](https://ollama.com)：

1. 安装 Ollama 并拉取模型：`ollama pull qwen3.5:4b`；
2. 保持 Ollama 运行（默认监听 `127.0.0.1:11434`）；
3. 在修图页点「AI 智能体」，可输入修图目标（如「风光通透」「胶片感」）。

行为说明：

- 程序**只发送照片的客观测量值**，不发送照片本身；
- Ollama 未运行时自动回退本地规则推荐并标注来源；
- 除回环地址外不访问任何网络。

> 2.40.0 起，**AI 分类与人脸功能已从这一节移出**——它们不再需要 Ollama 之外的任何服务（见第 11 节）。

## 10. 智能检索（图库聚类条）

图库上方聚类条提供四类**本地 AI 能力**（引擎随包、点按钮即用，启动方式见第 11 节），全程本机完成：

| 按钮 | 作用 | 产出 |
|---|---|---|
| **相册聚类** | 按省份 / 年份 / 城市 / 大区等维度自动分组 | 簇 chips，点击即筛选 |
| **相似照片** | MD5 + pHash 找出相似/重复照片 | 分组浏览对话框，可批量标记「待删」（非破坏性，可撤销）；私密照不参与 |
| **AI 分类** | 本地 CLIP 视觉塔（随包 `clipinfer.exe`） | **8 类场景标签**（人像 / 风光 / 夜景·星空 / 城市·建筑 / 微距·花卉 / 动物 / 美食 / 黑白）+ 兜底「其他」，chips 筛选 |
| **识别人物** | 本地 SCRFD 检测（随包 `faceinfer.exe`） | 人物标签写入，可右键重命名 |
| **智能聚类** | 本地 ArcFace 特征 + 两遍精炼聚类 | 自动归组「人物N」，可逐个改名 |

要点：

- **单张失败不中断整批**：某张照片坏图或引擎抖动时，该张被**放过**（不写标注），进度条继续走完。这是 2.40.0 的显式语义——不会出现「跑到第 3000 张整批崩掉」，也不会给坏图编一个标签。收尾提示只会说「中断（可能已部分写入）」，**不带精确失败张数**（计数目前只进程序日志，没做到弹窗上），重跑一次即可补齐未标注的照片。
- **智能聚类两遍精炼**：贪心种子 + 至多 3 轮质心迭代，结果不再依赖照片处理顺序、同人归组更准；一次性运算在后台进行，界面不冻结。
- **AI 写库单写者**：分类/识人等后台运算只计算，写回统一排队到界面线程执行，杜绝并发写库的数据竞争。
- **已标注的照片不会被覆盖**；聚类编号防撞号；多人合影按置信度最高的代表脸归类。

## 11. 本地 AI 引擎（随包独立子进程，**不需要启动任何服务**）

2.40.0 起，三个 AI 能力各自对应一个**随包的可执行文件**，由程序按需拉起为**子进程**，通过标准输入/输出传递帧消息（`READY` / `REQ` / `RES` / `ERR`）。

**没有 HTTP 服务、没有端口监听、没有需要你先双击的 `.bat`。** 旧版要求的 8766（场景分类）与 8767（人脸）两个端口在本版已彻底移除。

| 能力 | 引擎 | 包内位置 | 模型文件（与 exe 同目录） |
|---|---|---|---|
| AI 消除 | `inpaint.exe` | `3rdparty/lama/bin/` | `lama.onnx`（LaMa，Apache-2.0） |
| AI 分类 | `clipinfer.exe` | `3rdparty/clip/bin/` | `clip_vit_b32_img.onnx`（CLIP ViT-B/32 视觉塔）+ `prompts.bin`（8 类提示词矩阵） |
| 识别人物 / 智能聚类 | `faceinfer.exe` | `3rdparty/face/bin/` | `detection.onnx`（SCRFD-10GF 检测）+ `recognition.onnx`（ArcFace w600k_r50 识别） |

三个引擎都依赖 **ONNX Runtime 1.19.2**（MIT，随包 `onnxruntime.dll`）。`faceinfer.exe` 另需 `Qt6Core/Qt6Gui` 与 MinGW 运行库，以及 **JPEG 解码插件** `3rdparty/face/bin/imageformats/qjpeg.dll`——这张照片能不能被读进来，取决于这一小个文件在不在（见第 18 节）。

### 11.1 一次运算的时间花在哪里

- **首次拉起**要加载模型：人脸引擎实测 `READY` 约 **2.5 秒**（det+rec 两会话，合计约 191 MB），分类引擎实测在 **0.5–3.7 秒**摆动（视觉塔 351 MB）。程序给的等待预算分别为人脸 30 秒、分类 60 秒，足够容纳最慢的冷启动。
- 之后进程**常驻复用**，每张只需数百毫秒量级；一整库的批量运算成本主要在解码与读盘。
- 进程**保活、不因单张失败被杀**；协议不设「杀进程」码，取消只在批间/张间生效点被检查。

### 11.2 引擎读的是哪份数据

- **人脸识别读原图的绝对路径**，由子进程自己从磁盘读；程序不复制原片、不改写原片，也不把图像字节发给任何别的东西。
- **场景分类读库内缩略图**（分类只需要场景级判断，用缩略图换整库吞吐）。
- 两类都会**按 EXIF 方向摆正后再推理**（2.40.0 修正：手机竖拍原图在库里存的是旋转过的像素，摆不平会让检测器大面积漏检——这一条在门禁里有专门的一张 10 脸合影做回归夹具）。

### 11.3 出问题时你会看到什么

| 状态 | 你会看到 | 数据后果 |
|---|---|---|
| 引擎或模型文件缺失 | 点按钮弹出「**AI 引擎未就绪**（缺模型或引擎文件…）」，功能不启动 | 库完全不被触碰 |
| 引擎启动超时 / 崩溃 | 该轮如实报「中断（可能已部分写入）」，其余批次继续 | 已写入的部分保留，不写假标签 |
| 单张推理失败 | 该张被跳过（不标注），进度继续 | 该张保持未分类/未标注 |
| 你点取消 | 在下一次张间/片间检查点停下来，已完成部分照常写回 | 不丢已完成结果 |

> 包内**没有** `fetch_ai.ps1`（它属于源码树的准备脚本）。发布包用户遇到「引擎未就绪」，正确处置是：**重新完整解压**，或用包内 `MANIFEST.txt` 逐文件 `Get-FileHash` 比对，确认 `3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录完整。自建/源码树用户才需要跑 `native/fetch_ai.ps1` 取模型。

## 16. 已知边界（设计取舍，非缺陷）

| 项目 | 状态 |
|---|---|
| AI 分类标签集 | **8 类 + 「其他」**（人像 / 风光 / 夜景·星空 / 城市·建筑 / 微距·花卉 / 动物 / 美食 / 黑白）。旧版经由外部服务可返回的细粒度类目集合随该服务一并移除；库里**历史遗留的标签字符串仍能被正确识别与归一**（英文/近义词映射到同一档），不会因升级而丢失已有筛选 |
| 引擎首帧延迟 | 冷启动加载模型需要秒级（见 11.1），之后复用常驻进程；首次点击比后续慢是预期行为 |
| 单张失败与取消 | 采「放过当张、继续整批、收尾如实汇总」策略；中断轮次报「未完成」而非「成功」（2.40.0 收紧：全失败或被取消的轮次不再报成功） |
| 与参考实现的一致性 | 三个引擎都对着原 Python 参考实现做过**逐张对拍**：人脸脸数完全相同、框位 IoU ≥ 0.998、关键点平均偏差 ≤ 0.29 像素、特征向量余弦 ≥ 0.99923、置信度差 ≤ 0.001；场景分类判分极差 ≤ 0.0026。也就是说，你从旧服务迁过来会得到同样的结果 |
| ONNX Runtime 的 VC++ 运行库 | `onnxruntime.dll` 依赖系统的 `MSVCP140.dll` / `VCRUNTIME140.dll`（Visual C++ 2015–2022 可再分发库）。**本包未随附这四个 DLL**——近年的 Windows 桌面机器绝大多数已由其他软件装过它。完全没装过的机器上，三个 AI 功能会报「引擎未就绪」，其余功能正常（自 2.35.0 的 AI 消除起就是同一状况，本版未改变） |
| 人脸聚类耗时 | 两遍精炼为一次性后台运算，不阻塞界面 |
| 多人同框照片 | 按置信度最高的代表脸归为一人，不做逐脸分离 |
| 重新聚类 | 需先清空目标照片的人物标注（本版本不提供自动重置按钮） |
| 灯箱原图 | 后台渐进加载，超大图（约 4000 万像素以上）解码有预算保护，超时保持缩略图 |
| HEIC 抽取验证面 | 2.38.0 的 WebP/HEIC 容器解析在**字节确定的合成夹具**上恒绿并有越界/自指导致崩溃的反例守卫；真 `.heic` 样本臂需要用户显式提供样本文件才跑，本版**未经真机图片验证** |
| RAW / 视频 | 支持（解码缩略图、EXIF、抽帧、播放、磁盘缓存）；外部解码器缺失时对应格式优雅跳过 |
| 修图预览与导出 | 预览在 ≤1024 缩略图上执行、导出在 ≤2400 全分辨率重放。基于检测的算子（水平/红眼/美颜/暗角）导出结果可能在阈值附近比预览更精确；其余算子与几何链路预览=导出 |
| 界面图标 | 少量角落仍使用 emoji 字符图标；矢量图标体系在后续阶段铺开 |

## 18. 故障排查

| 现象 | 处理 |
|---|---|
| 启动报「库打开失败」 | 检查 `LA_DB` 路径是否存在/被占用；或用环境变量指向有效库 |
| 足迹省份为 0 | 正常现象之一：照片无 GPS 或落在覆盖范围外（诚实留空） |
| **AI 分类 / 识别人物 / 智能聚类 提示「AI 引擎未就绪」** | 本版**不需要启动服务**。请确认包解压完整：`3rdparty/face/bin/` 应有 `faceinfer.exe` + `detection.onnx` + `recognition.onnx` + `onnxruntime.dll` + `imageformats/qjpeg.dll`；`3rdparty/clip/bin/` 应有 `clipinfer.exe` + `clip_vit_b32_img.onnx` + `prompts.bin` + `onnxruntime.dll`。可用 `MANIFEST.txt` 逐个 `Get-FileHash` 比对，缺件就重新解压 |
| 文件明明都在，仍报「引擎未就绪」 | 两个方向：① 该机没装 Visual C++ 2015–2022 可再分发库（`onnxruntime.dll` 的依赖，见第 16 节）；② `3rdparty/face/bin/imageformats/` 被杀软或手工移走——此时**JPEG 一律读不进**，而 PNG 仍正常。表现就是「只有 JPEG 照片的人脸功能失败」 |
| 竖拍的手机照片检不到脸 | 2.40.0 起已按 EXIF 方向摆正后再检测。若你的库是在**旧版本**上做的标注，建议对这批照片重跑一次「识别人物」 |
| AI 消除提示「模型未就绪」 | 确认 `3rdparty/lama/bin/` 内执行器与模型文件完整（见第 17 节槽位说明）；缺失时相应功能诚实挂起，其余不受影响 |
| AI 消除点「应用」后显示处理中 | 正常——本地模型推理需要数秒，界面可继续操作，也可取消 |
| 第一次点 AI 分类比后面慢很多 | 正常——首帧要加载 351 MB 视觉塔（见 11.1） |
| 一整批跑完提示「中断（可能已部分写入）」 | 说明这一轮**不是干净跑完**（被取消，或有张失败）。已写入的标注是真实的，重跑只会补齐未标注的照片 |
| 智能聚类后人物分组不理想 | 先把分错的照片改名归并；两遍精炼倾向于宁可多分不漏合 |
| 高分屏下界面发糊 | 确认未强制 `QT_SCALE_FACTOR`；程序按系统缩放渲染 |
| 故事条分组不符合预期 | 「地点 + 时间窗口」启发式视图，非缺陷（见 4.1） |

## 19. 本版新增（随 2.38.0–2.40.0 一并纳入本发行）

### 2.40.0 · AI 引擎去外部化（本轮主线）

- **三个 AI 能力全部随包子进程化**：`clipinfer.exe`（CLIP ViT-B/32 + 8 类提示词矩阵）与 `faceinfer.exe`（SCRFD-10GF 检测 + ArcFace w600k_r50 识别）取代原先必须自行启动的两个 Python 服务。协议为 stdio 帧消息（`READY`/`REQ`/`RES`/`ERR`），**零端口、零 socket、零服务**。
- **降级语义收紧**：坏图或引擎抖动 → 放过当张、整批继续；被取消或全失败的轮次 → 返回值如实报「未完成」，不再出现「全失败也提示成功」。
- **两个用户可见修正**：① 人脸检测按 EXIF 方向摆正（否则手机竖拍原图大面积漏检）；② 引擎内的 JPEG 解码插件路径被打通（此前只有 PNG 解得动，实际后果是「人脸功能对 JPEG 库永远检不到脸」——两条都有负控实验取证）。
- **打包腿闭环**：`release.ps1` 新增第 10 条契约，在暂存树内以收缩 PATH 真跑 `faceinfer.exe --version`，并把人脸引擎的完整加载闭包（Qt6Core/Qt6Gui + MinGW 三件 + `imageformats/qjpeg.dll`）与两个模型的许可文本一起装进包；顺带闭环了 2.39.0 遗留的 `Qt6Concurrent.dll` 入包问题。
- **准备脚本**：源码树用户用 `native/fetch_ai.ps1` 取模型——**先算 SHA256 再落地**、落地后复核、许可文本缺失即拒绝装配，绝不把校验失败的字节放进部署目录。
- **与参考实现平价**：逐张对拍达标（见第 16 行的极值），门禁含**反例臂**（篡改期望值必然咬红，证明门不是空心）。

### 2.39.0 · 修图引擎提速（算子内并行 + 量化安全浮点）

- 热点循环并行化：高斯模糊（按行）、PIL 基础与中层色调映射族、光晕滤波族（中值/平滑/min）、红眼双 pass、暗角径向、镜头校正按瓦片。
