# 光影集 LightAlbum 2.42.0 · 使用说明书

> **定位声明**：LightAlbum（native 版）是唯一正式分发形态——一个**零云端、纯本地**的 Windows 桌面照片管理客户端。发行物为单文件压缩包 `LightAlbum-2.42.0-win64.zip`，解压即用；旧 1.x Python 打包版本已全部停发并清理。
>
> **本版能力面**：**常设展 · 今日一展（馆长选题）** / **凝视策展序列（自动逐帧 + 呼吸驻足）** / 前厅（今日回看 / 最新到馆） / 人物馆（一人一展室） / ⌘K 检索与跳转 / 展厅灯光（四灯可切） / 图库浏览 / 自动故事相册 / 相似照片去重 / 足迹地图（轨迹+热力+按年筛选+国家省市三级下钻） / 修图实验室（双引擎 + AI 消除真引擎 + 一键增强 13 算子） / AI 美图 / AI 场景分类 / 人脸识别与人物聚类（两遍精炼） / 隐私库（全链路一致过滤） / 中英双语 / 无障碍键盘操作 / 高 DPI 适配 / 统一动效引擎 / 设计语言 v2 / 原生导入器（含 iCloud 相册） / RAW 与视频 / HEIC·WebP 的 EXIF 容器抽取。所有处理均在你的电脑上完成，不向任何服务器发送照片或数据。
>
> **本版最重要的变化**：相册开始**主动开讲**。上一轮把 AI 索引搬进本机之后，能力面还是「被动检索」——照片得你先想好问法才见得到。本版把这些既有测量结果（场景分类、人物、EXIF、相似指纹、清晰度）**翻转为每周由本机出一版展**：前厅墙上出现一张**「今日一展 · 馆长选题」**卡，5–9 张照片、一个带张数的展名；点主图就走进**凝视策展序列**（自动逐帧，每帧驻足 2400 毫秒）。你只需要三种手势回应：**收进合集 / 换一展 / 别再这类**。
>
> 本版**没有新增任何运行时依赖**、**没有新增任何动效时长档位**（驻足用的是既有预设档位），压缩包体积与上一版持平。既有 AI 索引、修图与浏览能力**零改动**。

## 1. 安装与启动

1. 解压 `LightAlbum-2.42.0-win64.zip` 到任意目录（无需安装器、无需管理员权限、无注册表写入）。
2. 双击 `LightAlbum.exe` 启动。窗口标题显示「光影集 LightAlbum 2.42.0」。
3. **AI 素材已在包内**：`3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录连同模型一起解压即可用，**无需任何下载或服务启动**。
4. **首次使用**：程序启动后自动读取默认库，落在**前厅**；若库为空，前厅会引导你导入第一场展览（顶栏「导入」亦可）。

### 数据存放位置（默认，可用环境变量改）

| 内容 | 默认路径 | 环境变量覆盖 |
|---|---|---|
| 照片库（SQLite） | `D:\lightalbum\library.db` | `LA_DB` |
| 缩略图缓存 | `D:\lightalbum\thumbs\` | `LA_THUMPS` |

- 这两个路径与旧 1.x 版本**完全兼容**：已有库直接被读取，缩略图缓存互相命中，无需迁移。
- 若默认盘符不存在，可用环境变量指向任意位置，例如（CMD）：
  `set LA_DB=E:\photo\library.db` 后再启动。

### 本版给库文件加了什么

启动时会自动、幂等地补建四张新表（**不会**改动或删除已有照片、标注、评分）：

| 表 | 存什么 |
|---|---|
| `exhibits` | 每一版展：模板、展名、帧序、主图、生成时间、展示时间、你的回应（保留/换展/静音） |
| `albums` | 合集（本版只有「收进合集」写入，来源标记为 `curate`） |
| `album_items` | 合集里的照片与顺序 |
| `template_mutes` | 被「别再这类」静音掉的模板 |

另外：照片表里本来就有、但此前从未被读出的 `seen_at` 列，本版开始会被读取。**它是「扫描入库时间」，不是拍摄时间**——所以界面上的「新入藏」类展名说的是「什么时候进的库」，程序不会把它说成「拍摄于」。

## 2. 主界面

左侧图标栏**七区**，分三组：

| 分组 | 页 |
|---|---|
| 浏览 | **前厅** / **足迹** / **图库** |
| 人物·修图 | **人物馆** / **修图** |
| 工具 | **日志** / **关于** |

顶栏（在非前厅页显示）从左到右：页面标题、**💡 展厅灯光**（点开选四灯，见第 13 节）、**🔍 检索**（点开 ⌘K 面板，等同 `Ctrl+K`）、**导入**下拉、**隐私库锁**。

- **前厅零 chrome**：前厅页隐藏顶栏与控制簇（纯沉浸），只保留左侧全局导航。
- 顶栏**悬浮自动隐藏**：向下滚动时收起，鼠标移回顶部或滚回顶端时落下。
- 页面切换与局部反馈动效由统一动效引擎驱动（见第 18 节）。

## 3. 导入照片（原生导入器）

点击顶栏「**导入**」下拉，两个入口：

- **导入目录**：选择任意照片根目录（子目录递归扫描；`相机原始/缓存/回收站` 等辅助目录自动跳过）。
- **导入 iCloud 相册**：自动探测本机 iCloud 照片目录（`%USERPROFILE%\Pictures\iCloud Photos\Photos` 等三个候选路径），**空目录会被拒绝**以免误报「已找到」。

扫描在后台线程进行，不卡界面；可随时取消。完成后弹出汇总（新增/已存在/跳过）。

导入器行为细节：

- 读取每张照片的 **EXIF**（拍摄时间、相机、镜头、焦距、光圈、快门、ISO、GPS 坐标、方向等）——**缺失项如实留空**，显示为 `—`，绝不编造。
- 每次导入都会写下入库时间（`seen_at`），本版起策展引擎会读它，用于「新入藏」「搁了一年多」这类选题。

## 4. 前厅（今日回看与最新到馆）

进门第一屏，三块墙：

- **今日一展 · 馆长选题**（本版新增，见第 5 节）——有展时它是墙上的第一张卡，采用「开馆」高度层（金描边 + 内发光）。
- **今日展（往年今日）**：优先取「今年的今天」，不足 3 张逐级回退到**同月**、再**同季**；实在没有就安静显示「**今日无展 · 明日再会**」。**绝不拿别的照片凑数。**
- **最新到馆**：按入库时间倒序的最新一批。

前厅隐藏顶栏，但左侧导航、`Ctrl+K`、灯光与隐私锁仍然可用。锁定状态下私密照片不会出现在任何一块墙上。

## 5. 常设展 · 今日一展与三手势（本版核心）

### 5.1 一版展是怎么来的

程序在**启动时**与**你回到前厅时**各看一眼：距上一版成功生成**超过 7 天**才新开一版。

> 这不是定时器。没有常驻后台、没有 03:00 准点跑批——「每周」是**懒生成 + 7 天节流**的结果，机器不开就不会生成，也不会有任何进程在后台待着。

生成过程（**冷库门槛**：库里少于 50 张照片时不成展；50–199 张只用两枚低门槛模板「新入藏 / 搁了一年多」；200 张起 12 个模板全开）：

1. **候选池**：全库照片，剔除**私密照片**（隐私库锁定时）与**近 4 周内已展出过**的照片。
2. **按库温放行 12 个选题模板各出一题**（见 5.3），每题给出自己的话题键。
3. **打分**：`新鲜度 − 重复度`。**本版不做偏好学习**——你收藏了什么、看过哪些展，**不影响**选题分数（这是有意的取舍，见 5.4）。
4. **频控**：依次过「模板是否被你静音」「本周是否已展过一场」「同一个人 60 天内是否展过」。
5. **裁展**：把选中的帧**目标裁到 5–9 张**（候选比 5 还少就如实给更少，**不拿别的照片凑数**），用相似指纹去掉连拍冗余（指纹距离 ≤8 视为重复；去冗余的解码次数封顶 2 倍展内帧数，超顶后按廉价顺序补齐），再按**画质分**排序——画质分只在**展内帧**上算，不会拿去扫全库。
6. **定展名**：**只有裁完帧之后**展名才会产生，名字里的张数就是屏上真实帧数（「今年 · 7 张」= 7 帧，不是候选有 7 张）。
7. 结果回到主线程写库，前厅墙面重挂。生成期间界面不冻结。

任何一步凑不出可展的帧，就**整卡不出现**（不是渲染一张空壳卡），并在引擎内部如实记下跳过原因（如冷启动无历史、模板被静音）。

### 5.2 三种手势

卡上三个按钮，按下即刻落库，屏幕下方浮出回执。

| 手势 | 做什么 | 回执说什么 |
|---|---|---|
| **收进合集** | 以展名为名建一个**永久合集**，把这一展的帧（含顺序）写进去；并把这一展标为「保留」 | 「已把《…》的 N 张存为永久合集，**合集浏览下轮上线**。」失败时是「没能收进合集，库里没多出一份空壳。」 |
| **换一展** | 记下「换展」意图，并**立刻**新开一版（见下方频控说明） | 「已换一展。」若确实没有更多可展的照片：「暂无更多可展的照片，先补几张进来。」 |
| **别再这类** | **永久静音该模板**——这一展当场撤下，以后自动推送也不再出这类题 | 「这类展已安静下来。**反悔入口下轮上线**。」 |

关于「换一展」的口径，说清楚一点：

- 你按下按钮是**显式动作**，所以它**绕开 7 天节流**，并且**只放开「本周 ≤1」这一条腿**——模板静音、同人 60 天冷却**照旧生效**。周口径管的是**自动推送**，把你按下的按钮做成死键不是设计意图。
- 「换一展」后没有可展内容时，回执会**如实说没有**，不会假装换了。

关于**回执的措辞纪律**：界面上写出来的每一句都是承诺。合集的**数据**本版已真落库（可跨重启回读），但**还没有任何页面列出它**——所以回执明说「下轮上线」，不写「随时能再看」。「别再这类」同理，反悔入口没做就不承诺。

### 5.3 12 个选题模板与展名

展名由模板 + **真实展内张数**拼成，中英文都有译文。本版实际口径：

| 展名 | 这一版真的在选什么 | 需要什么前置数据 |
|---|---|---|
| 今年 · N 张 | 今年内拍的照片 | 拍摄日期（EXIF） |
| 旧识 · N 张 | 某一位人物的照片 | 已跑过「识别人物」 |
| 搁了一年多 · N 张 | 入库超过 1 年仍没被展过的 | 入库时间 |
| 一城 · N 张 | 同一城市的照片 | GPS + 离线逆地理编码 |
| 同一门类 · N 张 | 数量最多的那一个场景门类 | 已跑过「AI 分类」 |
| 黑白之间 · N 张 | 门类为「黑白」的照片 | 已跑过「AI 分类」 |
| 连拍那天 · N 张 | 同一天 ≥3 帧的日子 | 拍摄日期 |
| 在路上 · N 张 | 同城且跨 ≥2 天 | GPS |
| 那年今日 · N 张 | **仅固定公历节日**：元旦 / 劳动节 / 国庆 / 圣诞 | 拍摄日期 |
| 新入藏 · N 张 | 最近 14 天入库的 | 入库时间 |
| 夜色与远山 · N 张 | 门类为「夜景·星空」或「风光」 | 已跑过「AI 分类」 |
| 搁下两年 · N 张 | 入库超过 2 年的陈帧（方向 = 可退藏） | 入库时间 |

**四处展名与本版的真实取帧不同，按原设计名直译会夸大，因此改名如实记**：

| 本版展名 | 设计原名 | 本版为什么不用原名 |
|---|---|---|
| 同一门类 · N 张 | 「满墙皆青」 | 只按场景门类出题，**主色聚类未接**（设计文档已标 v1 降级） |
| 在路上 · N 张 | 「沿着海岸线走的那天」 | 只做「同城跨日 ≥2 天」，**轨迹连续段未接**（设计文档已标 v1 降级） |
| 今年 · N 张 | 「那年今天 / N 年前的 M 月」 | 本版选的是**当年整桶**，不做「N 年前的同月日」对照，所以不叫「那年今天」 |
| 搁下两年 · N 张 | 「可以退藏的 N 张」 | 本版出题只用「入库超过 2 年」这一个代理条件（连拍冗余/模糊那套完整巡检只存在于引擎里，**没有界面**），所以不叫「可以退藏」，也不许暗示能一键退藏 |

名字不许承诺数据没做的事，也不许承诺界面没给的按钮。

**农历节日不做**（元旦/劳动节/国庆/圣诞之外一律不出题），因为农历日期需要按年表近似，本版不接受猜。

### 5.4 本版明确不做的

- **偏好学习**：收藏明细与展出历史不参与打分（代码里这一项权重字面为 0，并有门禁守着它不许被接上）。
- **合集浏览页**：数据真落库，页面没有（见 5.2）。
- **「别再这类」的反悔 UI**：静音是永久写库，本版只能在库里清；设置页入口留后。
- **真实定时推送**：见 5.1。
- **废片巡检**：引擎侧的批量巡检函数已就绪（连拍冗余 + 糊图 + 陈旧帧三规则，RAW/视频按既有铁律豁免），但**本版没有任何页面上它**——界面上看不到、也点不到。它**永不删除**任何文件，这一点由门禁断言守着。

## 6. 凝视模式（沉浸看展 · 含策展序列）

把「一张一张翻」变成「站在画前」。入口有四个：**前厅厅心**、**今日一展卡的主图**、**人物馆展室**、**图库双击**。

- **无边框全屏 + 悬停雾条**：平时画面干净，鼠标动一下才浮出操作；主色调**实时取自当前照片**（缩略图中心加权中位数饱和色）成为一圈环境光晕——照片色彩冷时自动改用当前**展厅灯**的辅助色，不会糊成一块。
- **翻页即换展**：上一张淡出、下一张携光入位，同屏最多两张，**任何输入都能打断**。

### 6.1 策展序列（本版新增）

从**今日一展卡的主图**进入时，不是打开一张照片，而是**开一整展**：

- **自动逐帧**：帧序 = 展帧序（画质最高的帧先出，即卡上的主图），每张驻足 **2400 毫秒**（这一档时长来自统一动效引擎的既有预设，界面上不写死毫秒，也不可通过设置调整）。
- **展名小记字幕**：底栏在展期间显示**展名**（有「小记」时以 `展名 · 小记` 形式显示）。本版展名带真实张数（如「在路上 · 8 张」）。
- **随手可退**：除 `S`/`A`/`Delete`/`L` 四个表态键之外的**任意按键**、或画面/窗口上的**任意点击**，都等于「你把控制权拿回来了」——立即退展，停止自动逐帧，字幕交还照片自己的地点·日期·器材，`←`/`→` 回到手动翻图语义。
- **表态键不打断**：`S`（喜欢）/ `A` 或 `Delete`（略过）/ `L`（封存）在序列内照常可用，边看边标；若它们也打断，策展序列就没法标注了。
- **退展不留残影**：退出后底栏绝不残留上一展的展名。
- **展帧不在库里就不接管**：如果这一展的帧一张都不在库中，程序不开序列、不假装开展。

### 6.2 键盘表态（所有入口通用）

`S` 表示喜欢、`Delete` 或 `A` 表示跳过、`L` 表示锁定防误删。**按下的瞬间就写库**（单事务原子写），屏幕下方浮出 3 秒提示条——反悔就**再按同一个键**撤销。这三种标记与图库里的评分/私密/待删是同一套数据，改一处处处一致。翻图仍可用 `←` / `→`，`Esc` 退出。私密过滤在凝视模式下同样生效。

## 7. 图库（浏览与筛选）

- 网格浏览、按年/月/人物/门类/地点筛选、评分与标记、批量操作。
- 双击任意照片进入凝视模式。
- 隐私锁定状态下私密照片不出现在网格、筛选计数与聚类里。

### 7.1 相似照片去重

图库聚类条上的「相似照片」沿用原选片页的引擎（感知哈希 + 汉明距离），**逐张比对全部在本机完成**；私密照片不参与比对。

### 7.2 自动故事相册

按「地点 + 时间窗口」启发式分组，是**呈现视图**，不写库、不改文件。

## 8. 人物馆（一人一展室）

把一个「人」当作一间**展室**：展室名是人物名，墙上是他的照片。

- **展签卡**：一位人物一张装裱卡（白色卡纸 + 投影，悬停镀金），显示姓名、照片数与时间跨度（如 `2019–2024`）。
- **展室视图**：点开后按**年份分桶横向串联**，照片按时间铺陈，点任意一张进入凝视模式。
- 点展签右侧可**跳去图库按这个人筛选**（与图库人物条、⌘K 的人物词典共用同一套状态）。
- **空态**：还没识别过人物时显示「**馆内布展中**」，一键调用**识别人物**（第 16 节）。
- **隐私一致**：私密照片不会让一个人的展室凭空多出内容，也不会把只出现在私密照片里的人列进来。
- 「旧识 · N 张」这一选题用的就是人物馆的聚合结果；人物**以名字为键**，改名会让历史展的「同人 60 天冷却」判定断档——这是本版接受的脆弱性，如实记在这里。

## 9. 足迹（地图）

## 10. 修图实验室（核心）

`修图` 页，全部处理零云端：

- **手动滑杆 12 项**：曝光 / 亮度 / 对比 / 清晰 / 自然饱和 / 饱和 / 色温 / 色调 / 锐化 / 高光 / 阴影 / 暗角；

  - **诚实反馈**：红眼修复的命中点数、肤色占比、水平校正的角度都会如实报出；判定为「无倾斜」的校正明确提示**不改动**。
- **撤销栈**：任一步可回退；
- **几何编辑**：旋转、翻转、拉直 ±10°、比例裁剪与交互裁剪；
- **画笔蒙版**：局部涂抹后色调只作用于涂抹区域；
- **对比视图**：左右分割线对比原图与修后；
- **导出副本**：预览所见即导出所得；
- **★AI 消除**：涂抹要移除的物体，本地 LaMa 模型补全背景。执行器是**独立子进程**，零云端、崩溃只影响当次任务、自动重拉；推理在专属线程，**秒级计算期间界面完全不冻结**，可看到「处理中」状态并可取消。未随附模型时诚实提示「模型未就绪」，绝不假成功。
- **图像处理速度**：热点循环为**算子内按行/按瓦片并行**（可用 `LA_LUMEN_THREADS=1` 退回串行）。并行与串行结果**逐字节相等**。

## 16. 本地 AI 引擎（随包独立子进程，**不需要启动任何服务**）

三个 AI 能力各自对应一个**随包的可执行文件**，由程序按需拉起为**子进程**，通过标准输入/输出传递帧消息（`READY` / `REQ` / `RES` / `ERR`）。

**没有 HTTP 服务、没有端口监听、没有需要你先双击的 `.bat`。** 旧版要求的 8766（场景分类）与 8767（人脸）两个端口已彻底移除。

| 能力 | 引擎 | 包内位置 | 模型文件（与 exe 同目录） |
|---|---|---|---|
| AI 消除 | `inpaint.exe` | `3rdparty/lama/bin/` | `lama.onnx`（LaMa，Apache-2.0） |
| AI 分类 | `clipinfer.exe` | `3rdparty/clip/bin/` | `clip_vit_b32_img.onnx`（CLIP ViT-B/32 视觉塔）+ `prompts.bin`（8 类提示词矩阵） |
| 识别人物 / 智能聚类 | `faceinfer.exe` | `3rdparty/face/bin/` | `detection.onnx`（SCRFD-10GF 检测）+ `recognition.onnx`（ArcFace w600k_r50 识别） |

三个引擎都依赖 **ONNX Runtime 1.19.2**（MIT，随包 `onnxruntime.dll`）。`faceinfer.exe` 另需 `Qt6Core/Qt6Gui` 与 MinGW 运行库，以及 **JPEG 解码插件** `3rdparty/face/bin/imageformats/qjpeg.dll`。

### 16.1 一次运算的时间花在哪里

- **首次拉起**要加载模型：人脸引擎实测 `READY` 约 **2.5 秒**，分类引擎实测在 **0.5–3.7 秒**摆动。程序给的等待预算分别为人脸 30 秒、分类 60 秒。
- 之后进程**常驻复用**，每张只需数百毫秒量级。
- 进程**保活、不因单张失败被杀**；取消只在批间/张间检查点被检查。

### 16.2 引擎读的是哪份数据

- **人脸识别读原图的绝对路径**，由子进程自己从磁盘读；程序不复制原片、不改写原片。
- **场景分类读库内缩略图**。
- 两类都会**按 EXIF 方向摆正后再推理**。
- **策展引擎读的只有缩略图**：去冗余用缩略图算相似指纹，画质分用缩略图算清晰度与曝光分布。**它不会为选题去解码全库原片**——解码次数被红线钉在「展内帧数」以内（≤9 次）。

### 16.3 出问题时你会看到什么

| 状态 | 你会看到 | 数据后果 |
|---|---|---|
| 引擎或模型文件缺失 | 点按钮弹出「**AI 引擎未就绪**（缺模型或引擎文件…）」，功能不启动 | 库完全不被触碰 |
| 引擎启动超时 / 崩溃 | 该轮如实报「中断（可能已部分写入）」，其余批次继续 | 已写入的部分保留，不写假标签 |
| 单张推理失败 | 该张被跳过（不标注），进度继续 | 该张保持未分类/未标注 |
| 你点取消 | 在下一次检查点停下来，已完成部分照常写回 | 不丢已完成结果 |
| 策展生成算不出可展的帧 | **前厅不出现今日一展卡**（不是空卡） | 库里不写空展 |

> 包内**没有** `fetch_ai.ps1`（它属于源码树的准备脚本）。发布包用户遇到「引擎未就绪」，正确处置是：**重新完整解压**，或用包内 `MANIFEST.txt` 逐文件 `Get-FileHash` 比对。

## 22. 故障排查

| 现象 | 处理 |
|---|---|
| 前厅没有「今日一展」卡 | 四种正常情况：① **库里少于 50 张照片**（冷库不成展，见 5.1）；② 50–199 张时只有「新入藏 / 搁了一年多」两枚低门槛模板可用，两者都凑不出帧就没有展；③ 可用的模板都被「别再这类」静音了，或本周已展过一场且没有其他候选题；④ 候选帧全部已被近 4 周展出过。**不是加载失败**，也不会渲染一张空卡 |
| 展卡上的张数和实际看的帧数一致吗 | 一致。展名在裁完帧之后才产生，名字里的数字就是屏上的帧数 |
| 点「收进合集」后找不到合集 | 本版**尚无合集浏览页面**（回执已明写「下轮上线」）。数据在库里的 `albums`/`album_items` 两张表中，页面下一轮补 |

| 「换一展」点了没换 | 说明**确实没有别的可展内容**——回执会说「暂无更多可展的照片，先补几张进来」。注意模板静音与同人 60 天冷却对「换一展」同样生效（只有「本周已展过一场」这条被放开） |
| 凝视序列自动翻到下一张，我想停下 | **按任意键**（表态键 `S`/`A`/`Delete`/`L` 除外）或**点一下画面**即可退展；之后 `←`/`→` 回到手动翻图 |
| 驻足太快 / 太慢，能不能调 | 本版固定为 2400 ms（引擎预设档位），不提供滑杆。见第 21 节的说明 |
| 英文界面看到 `curate.tmpl.*` 之类的键名 | **不应发生**——本版已把这批展名改为真正的译文并有门禁守着。若你看到，请报告（附截图与语言设置） |
| 竖拍的手机照片检不到脸 | 已按 EXIF 方向摆正后再检测。若库是在更旧版本上标注的，建议重跑一次「识别人物」 |
| **AI 分类 / 识别人物 提示「AI 引擎未就绪」** | **不需要启动服务**。确认包解压完整（见 16.3），可用 `MANIFEST.txt` 逐个 `Get-FileHash` 比对 |

## 附录 A：校验与复现（进阶）

发行包内附两个可校验文件：

- **`BUILDINFO.txt`**（SBOM 溯源）：本包由哪个 git commit、哪套 Qt / 编译器、哪种构建类型产出。
- **`MANIFEST.txt`**：包内**每一个文件**的 SHA256 与字节数，可用 `Get-FileHash` 逐个复核。

源码树用户可自行验证发布契约：`powershell -File native/release.ps1 -SelfTest` 跑打包契约自检，**10 条**（版本同步 / 手册内容一致 / 核心产物 / 清单一致 / 许可证 / 构建类型为 Release / AI 消除许可 / 人脸与分类许可 / 引擎在收缩 PATH 下的真实可执行性）。

回归门禁面为 **80 道门**（**22 道秒级快门 + 58 道全量门**），覆盖导入/浏览/修图/地图/隐私/双语/动效/设计债棘轮，三条引擎契约门、两条真模型对拍门，以及本版新增的 **`LA_CURATE_QA`（139 条断言腿）**。

新门在名册里**归全量层而不是快门层**，这是实测结果不是偏好：同一把尺子量下来它暖样本 1508–1800 ms（一次冷离群 9983 ms），因为要起完整 QApplication 并建三份合成 SQLite 夹具。计划原本写「fast 层 / 快门 23 道」，实测否掉了这个口径，真实名册是 **22 fast + 58 full**。

`LA_CURATE_QA` 带七个「反例臂」——故意改坏被测的那件事，门必须变红；红不了就说明门是空的：

| 臂 | 改坏的事 | 必须红的组 |
|---|---|---|
| `LA_CURATE_QA_FORCE_BROKEN=1` | 把偏好权重接上 | E（打分不许被偏好污染） |
| `..._H=1` | 把画质塞进去重签名 | H |
| `..._Q=1` | 对全候选集解码算画质 | V（成本红线） |
| `..._I=1` | 让巡检去删除 | I（永不删除） |
| `..._R=1` | 让落库在后台线程内联跑 | R（GUI 单写者） |
| 手工变异（展名轨 5 轮） | 键回表 / propose 就填名 / compose 清空展名 / 展名报候选数 / 译文写成中文 | N（展名本地化） |
| 手工变异（回执轨 2 轮） | 中文/英文回执改回「随时能再看」 | `M_ack_keep_honest` / `LA_I18N_QA` |

## 附录 B：从 2.41.0 及更早版本升级，我该注意什么

1. **前厅多了一张卡**：「今日一展 · 馆长选题」。它不是通知、不是广告，也不会弹出来——它只是墙上的一张卡，你可以完全不理会它。
2. **库文件会自动补四张表**（`exhibits`/`albums`/`album_items`/`template_mutes`），幂等迁移，**不动照片、评分、人物标注、私密标记**。反向兼容：老版本读新库会忽略这四张表，不会崩，但看不到策展历史。
3. **凝视模式的行为只多不少**：从今日一展卡进去才走自动逐帧；从前厅厅心、人物馆、图库进去仍是原来的手动凝视。任何一键/点击即可退回原语义。
4. **表态键的写库路径没变**：`S`/`A`/`L` 仍写既有标记列，与图库工具条同源。
5. **颜色与版式默认没变**：默认灯仍与旧配色逐字节相同；新增的高度层只作用于今日一展卡与 ⌘K 面板。
6. **AI 行为与上一版一致**（随包子进程、无需服务、估价与降级语义不变）。
7. 从 ≤2.40.0 升上来时，另请参阅上一版手册的附录 B（AI 服务退役、压缩包体积、竖拍照片建议重跑识别人物）。

## 23. 本版新增（2.42.0）

### 策展系统 v1「常设展」
- **12 个选题模板**全量入册，缺数据源的模板**返回空 + 跳过原因**，绝不伪造照片；两处降级（主色、轨迹）如实记在文档与代码注释里。
- **打分 = 新鲜度 − 重复度，偏好项字面为 0**（本版无偏好学习），并有反例臂守着它不许被接上。
- **频控四条腿**：懒生成 + 7 天节流（**非定时器**）、每周 ≤1、同人 60 天冷却、模板永久静音。
- **展名诚实**：展名在裁完 5–9 帧**之后**才产生，名字里的张数 = 屏上帧数；命名跟着数据口径改，不承诺数据没做的事。
- **画质只在展内**：解码次数上界 = 展内帧数（≤9），不再对候选集逐张解码。

### 界面与交互
- **今日一展 · 馆长选题卡**（前厅，开馆高度层 + 一次呼吸光晕，非循环）+ 三手势 **收进合集 / 换一展 / 别再这类**，每条回执都有实测过的反例臂守着「不许空头承诺」。
- **凝视策展序列**：自动逐帧 + 2400 ms 呼吸驻足（既有档位）+ 展名字幕；除表态键外任意输入即退展，退展不留展名残影。
- **三个新矢量图标**（馆长 / 上下双箭头 / 圆内斜杠）+ 高度层补 **E3 聚光 / E4 开馆**；「收进合集」复用既有星形图标。

### 数据与工程
- 库新增 4 张表 + 7 个 Library API；`Photo::seenAt` 补入 SELECT（**入库时间，非拍摄时间**）。
- 编排层线程纪律：**纯函数选题 + 后台计算 + `QueuedConnection` 回 GUI 落库**，后台线程绝不触 SQLite；三手势的落库只有一份真源。
- 门禁名册 **79 → 80**（`LA_CURATE_QA`，139 条腿）；名册按实测归**全量层**，`measuredMs` 由 `-Timing ×15` 暖样本回填（1900 ms）。
- 英文目录 **347 → 368 条**（0 未完成），`.ts` 与编译后 `.qm` 同批提交。
- **反例电池 7 轮全部实跑**，还原后工作树与基线逐字段相同。

### 收口时抓到并修掉的两个非策展缺陷
- **前厅/人物馆缩略卡崩溃**：待决缩略回调用「已被释放的卡片」当守卫，缓存重建时踩空——上一版的两张页面就是这条路径。本版改为按路径回查，修好后四道此前闪断的门恢复。
