## 2. ★ 关键运维发现（必读，否则门禁全「无输出」假阴性）

**原生 Windows Qt exe（MinGW 编出）在 Git Bash（MSYS）下运行会吞掉全部 stderr/stdout——进程 exit 0、0 字节，看似「门禁无输出/秒退」，实为 shell 吞输出，不是产品缺陷。**

实证：同一二进制，Git Bash（`env QT_QPA_PLATFORM=offscreen LA_XXX=1 ./build/LightAlbum.exe`，前台/后台/`timeout`/`env`/文件重定向 全部 0 字节）；**改用原生 PowerShell（`& $exe 2>&1`）立即正常输出 `DBG0 main entered` + 各门结论**。

**规则：跑所有门禁用 PowerShell，不要用 Git Bash。** 已确认 Git Bash 在本机对本 exe 不可靠（疑 MSYS 对原生子系统进程的输出接管异常）。

### 2.1 推荐运行片段（已验证）

```powershell
$exe = "D:\Test\workbuddy\2026-09-18-09-00-13\native\build\LightAlbum.exe"
$env:QT_QPA_PLATFORM = "offscreen"
$env:LA_GEO_SMOKE = "1"          # ← 换成目标门；自退门直接返回，挂起门打印后常驻
& $exe 2>&1 | ForEach-Object { $_.ToString() } | Where-Object { $_ -match "LA_|GEO" }
# 挂起类门（地图/截图）打印后进入事件循环常驻，工具超时即被杀死；
# LA_ 结论行已在超时前流式输出，可直接读取。需要显式收尾时另开一条：
#   Stop-Process -Name LightAlbum -Force
```

> 注意：`Start-Job` / `Start-Process -RedirectStandard*` 在本机 PowerShell 策略下被拦或撞 `Path/PATH` 大小写冲突 bug，**不要用**。直接 `&` 管道最稳。

### 2.2 门禁两类行为（实测纠正：全部自退，无需手动 kill）

**重要纠正（2026-10-02 本轮 dogfooding 发现）**：早期把 `LA_MAP_*` 等门判为「打印后常驻、需外部 kill」，是 **Git Bash 吞输出**造成的错觉——实际在 PowerShell 下它们**全部自退**。

- **硬自退门**（在 `app.exec()` 前 `return`，秒退，不加载真库）：`LA_LUMEN_SMOKE` `LA_AGENT_SMOKE` `LA_GEO_SMOKE` `LA_SCAN_SMOKE` `LA_ICLOUD_QA` `LA_EXIT_QA` `LA_LOG_SMOKE` `LA_HOME_SMOKE` `LA_RW_SMOKE`。
- **构造后自退门**（MainWindow 构造 + `win.show()` 后直绘离屏，打印 `*_DONE` 即 `return 0`；因要加载真库+建地图，耗时数秒但**必自退**，不是常驻）：
  - 地图系列：`LA_MAP_A_QA` `LA_MAP_REGION_QA` `LA_MAP_CLICK_QA` `LA_MAP_BURST_QA` `LA_MAP_PERF` `LA_MAP_COUNTRY_QA`、`LA_MAP_SMOKE`（已删，见台账）。
  - 控件系列：`LA_GALLERY_E_QA` `LA_GALLERY_FILL_QA` `LA_RETOUCH_A_QA` `LA_CULL_SMOKE` `LA_RETOUCH_SMOKE`。
  - 截图/集成：`LA_SPLASH_SHOT`（定时器 2450ms→quit 自退）、`LA_LIGHTBOX_SHOT` `LA_LOG_SHOT` `LA_HOME_SHOT` `LA_UI_SHOT` `LA_SMOKE`（载入真库后自退）。
- **结论**：所有门禁都自退。所谓「常驻需 kill」是 Git Bash 吞输出假象，不必 `Stop-Process`。runner 的 kill 仅是超时安全网。

> 直绘自退的原理：地图/控件 QA 门不依赖事件循环，直接用 `QPainter` 离屏渲染到 `QImage` 并 `save`/` fprintf`，随即 `return 0`，进程结束。详见 `src/main.cpp` 各 `if (!qEnvironmentVariableIsEmpty("LA_xxx")) { ...; return 0; }` 块。

### 2.2.1 ★★ 自退时序铁律（2.7.0 新增，违反即静默挂死）

**`[KILL]` 不一定是环境问题 —— 2026-10-03 已实证它可以是代码缺陷，而且是最容易被误判的一类。**

`QApplication::quit()` 的真实语义是「给**当前**事件循环发退出信号」。**若在 `app.exec()` 之前调用，它什么都不做（no-op）** —— exe 会打印完全部断言、然后照常进入 `app.exec()` 永久空转。最小复现（探针实测，非推断）：

| quit 时机 | 结果 |
|---|---|
| `exec()` **之前**调用 | `RC=124` 挂死，exec() 照常进入永不返回 |
| 事件循环**内**（timer）调用 | `RC=0` 正常退出 |

真实事故：`LA_CULL_SMOKE` 的自测钩子在 `CullPage` **构造期**同步 `autoRun(80)` → `onFinished()` 直接 `quit()`，而 `exec()` 在 `main()` 末尾才进入。表现是门禁 `[KILL]`，历史上被归入「控制台依赖 / 环境族」放过了多轮。**修掉后 `RC=124` → `RC=0` / 3.9s 自退，输出逐字节一致（250 bytes）。** 全量回归因此首次达到 `KILL=0` 全绿（28 门）。

由此确立三条铁律（已焊进 `src/core/qaExit.h`）：

1. **任何门禁/探针要退出进程，必须经 `QaExit::requestExit()`**，禁止裸调 `QApplication::quit()` / `QCoreApplication::exit()`。现在 `src/` 下裸调用为 0（仅 `qaExit.cpp` 实现内部与注释命中）。
2. **绝不「判断是否在事件循环内再决定同步还是异步」**。Qt 无公开 API 判断该状态，猜错就是挂死。`requestExit()` 无条件走 `QTimer::singleShot(0, ...)`：构造期注册也会在 `exec()` 启动后触发，事件循环内调用仅延迟一个事件迭代（~0ms）——**一条路径覆盖两种时机**。
3. **看门狗 `QaExit::armWatchdog()` 是最后一道防线**，抓「事件循环活着但无人请求退出」。要点：
   - 挂载点必须**在任何分支之前**（紧跟 `QApplication` 构造）。曾挂在 `MainWindow` 构造前，结果 `LA_EXIT_PROBE` 子进程入口走不到 —— **是 `LA_EXIT_QA` 的 E5 断言当场抓到这个盲区的**，不是靠事后复盘。
   - 预算（默认 20s，可由 `LA_WATCHDOG_MS` 覆盖）**必须 < runner 的 `-Timeout` 25s**，否则 runner 先 kill，只剩无信息的 `[KILL]`，拿不到归因。
   - 归因必须**指名门名**（`LA_GATE` 由 runner 显式设置）。
   - 仅在检测到 `LA_*` 变量时挂载 —— 真实交互启动不挂，**绝不会杀用户进程**。

**新增/改动门禁时的自检清单**：
- 门禁退出是否经 `QaExit::requestExit()`？（`grep -rn "QApplication::quit" src/` 应只命中 `qaExit.*`）
- 断言是否覆盖「时序」这类**行为契约**，而不只是返回值？
- **反例验证做过没有**：把实现改回缺陷形态，门禁是否真的变红？`LA_EXIT_QA` 已实测 —— 注入同步 `exit()` 后 `fails=2` RED，且真实门被看门狗以 `rc=3` 抓住。

### 2.2.2 ★★ 门禁矩阵铁律（2.8.0 新增，分层必须由实测而非直觉决定）

**门表与分层的唯一真源是 `native/gate_matrix.ps1`。`qa_runner.ps1` 不再内嵌门表。**

**为什么**：此前门表内联在 runner 里，门只有一处，但**成本不可见** —— 30 门在每个 PR 上全量跑。2026-10-03 用 `qa_runner.ps1 -Timing` 实测基线：

| 类别 | 门数 | 单门耗时 | 共因 |
|---|---|---|---|
| 纯逻辑门 | 9 | 56 - 250 ms | `main()` 早期 return，不构造 MainWindow |
| 构造 / fixture 门 | 21 | 338 - 8662 ms | 构造 MainWindow 或载入 6425 张 fixture |

**77% 的门只占 2% 的时间**，而 PR 每次都付 73.6s。分层就切在这条实测边界上：
**fast 层 9 门 1.74s，全量 30 门 73.4s（42 倍）**。

**分层语义（三条铁律）**：

1. **tier 缺省 = `full`（fail-safe）**。新门忘写 tier 只会落进最严的一层，**绝不会因遗漏而静悄悄削弱 PR 层**。`LA_GATE_MATRIX_QA` 的 E3 断言实测了这一点：剥掉所有 tier 后 fast=0 / full=30。
2. **不传 `-Tier` 就是两层并集**，与 2.7.0 行为逐字节一致。`release.ps1` 与本地全量跑都用并集 —— **打包门禁强度未被矩阵化削弱**。`iterate.ps1` 报告里会打印 `tier=`，避免把 9 门报告误读成全套通过。
3. **PR=fast / main+tag=full**，选择发生在 `.github/workflows/qa.yml` 里唯一一处，并写入 `$GITHUB_ENV`，层级出现在 CI 日志与 artifact 名前缀。

**两处刻意的排除**（理由写在 `gate_matrix.ps1` 头注释，不可省略）：

- `LA_SCALE_PERF`（338 ms）虽快，但断言**墙钟预算**，上共享 CI runner 必 flaky。
  **PR 层放一个会抖的门，等于教人无视红色，比慢门更糟。**
- `LA_RW_SMOKE`（1017 ms）临界，留在严层，让 vault / 加密往返只有一处能坏。

**分层成分规则（不是比例规则）**：

- **E6**：fast 层每门 `measuredMs ≤ 500ms`；
- **E7**：5 个核心不变量门（`LA_GATE_MATRIX_QA` `LA_RETOUCH_UNDO_QA` `LA_GALLERY_SEARCH_QA` `LA_THUMB_CACHE_QA` `LA_GALLERY_BATCH_QA`）**必须**留在 fast 层；
- **E8**：每门必须带 `measuredMs`，否则分层就成了猜。

**★ 反例实测打穿过这三条规则（必读）**：首轮 E6 写成"fast 占比不超过一半"，把 3640 ms 的地图门塞进 fast 层后 fast=10/30，仍"不到一半" → **依然绿**。**比例规则根本看不见成分退化。** 已改为成员资格规则。另有一条反例最初写成"删 tier key 应变红"，它保持绿色**是正确的**（无 tier 本就该落严层），真正暴露的问题是**没有任何规则能察觉核心门离开 PR 层** —— 由此才有 E7。

**教训（结构化数据批改）**：给门表批量追加 `measuredMs` 时，字段被拼进了 `LA_RELEASE_QA` 的**带引号 `scriptArgs` 字符串内部**（`scriptArgs="-SelfTest; measuredMs=3135"`），键消失、参数被改。**E8 就是为这类"静默吞字段"而设的。批改结构化行必须逐行断言形状，不能只断言行首前缀。**

**`LA_GATE_MATRIX_QA` 住在 fast 层** —— 矩阵的看门狗自己必须在 PR 层被看。
18 条断言：E1 真表合规 / E2 互斥且并集完整 / E3 fail-safe / E4 严层装着贵门 / E5 fast 层无脚本门无 env 门 / E6 成本预算 / E7 核心门在位 / E8 每门有实测耗时 / E9a-g 七组同源反例 / E10 未知 tier 抛异常。
反例外部实测 **6/6 全部变红**（`_ce324.py`，逐个注入真实缺陷走真 runner）。

**新增/改动门禁时的自检清单（补充 §2.2.1）**：
- 新门的 `measuredMs` 填了吗？tier 想清楚了吗（不填 = 严层，安全默认）？
- 它属于 fast 还是 full？理由是**实测耗时**还是"我觉得它很快"？
- 反例注入后门真的红了吗？（`native/_ce324.py` 是 2.8.0 的证明模板）

### 2.3 下一代迭代指导：一键门禁 runner（`native/qa_runner.ps1`）

把本 SOP「必须用 PowerShell 跑门禁」的要求**固化成可执行脚本**，迭代结束一键跑全部门禁出绿/红报告。这是「下一代迭代指导」的落地形态。

**为什么需要它（踩过的坑，已焊进脚本）**：
1. **必须 PowerShell**：原生 exe 在 Git Bash 下输出被吞（§2），脚本本体只服务于 PowerShell 调用方。
2. **`.ps1` 必须纯 ASCII**：Windows PowerShell 5.1 读无 BOM 的 UTF-8 `.ps1` 会按 GBK 解析，中文字符串直接报「字符串缺少终止符」导致脚本加载失败。故脚本注释/提示**全英文**。
3. **禁用 `Start-Process`**：本机 shell 环境同时继承 `Path`/`PATH`/`path` 多份大小写变体，`Start-Process`（含 `-RedirectStandard*`）构建环境字典时抛 `已添加项...Path/PATH` 冲突。改为用 .NET `[System.Diagnostics.Process]` 直连 `CreateProcess`（大小写不敏感，无字典冲突），并用 `WaitForExit(timeout)+Kill` 兜底超时安全网。
4. **禁用三元运算符 `? :`**：PowerShell 5.1 不支持，用 `if/else`；`-match` 数组 `.Count` 用 `@(...)` 包裹防单元素退化。

**用法**：
```powershell
cd D:\Test\workbuddy\2026-09-18-09-00-13\native
# 跑全部门禁（默认超时 25s/门；自退门不会等到上限）
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1
# 只跑单门
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Only LA_GEO_SMOKE
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Only LA_MAP_CLICK_QA
# 指定 exe 路径 / 调超时
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Exe <path> -Timeout 40
# 分层（2.9.0）：PR 层 9 门 ~1.7s / 严层 22 门 ~72s / 不传 = 并集 31 门
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Tier fast
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Tier full
# 每门墙钟（分层依据，绝不靠猜）
powershell -ExecutionPolicy Bypass -File .\qa_runner.ps1 -Timing
```

> `-Tier` 与 `-Only` 都必须**拆成两个 argv token**（`& powershell -File` 的解析规则，见 §2.4）。

**输出**：逐门 `门名 [OK]/[FAIL]/[NOOUT]/[??]`，末尾 `=== SUMMARY: PASS=x FAIL=y CHECK=z ===`，并以 `FAIL>0` 设退出码（便于 CI `if (!$LASTEXITCODE)` 判定）。`[??]`=CHECK（有输出但无明确绿标，按 §3 人工核对）。

**判定逻辑（`Eval`）**：含 `FAIL` 或（非 kill 门）非零退出 → 红；含 `PASS|OK|DONE|done|rings=|Loaded|loaded=` → 绿；零输出 → `NO-OUTPUT`；其余 → `CHECK`。

**当前门清单**：**31 门**（2.9.0），全部在 `src/main.cpp` 实证存在，清单与分层见 §2.2.2 与 `native/gate_matrix.ps1`。`LA_MAP_SMOKE` 已确认不存在，已从清单移除。`[??]`=CHECK 表示有输出但无明确绿标，按 §3 人工核对。

> 2.9.0 新增 `LA_HIDPI_QA`（方向 F 第一步·高 DPR 渲染）：HiDpi 烘焙唯一真源 + `MapView` 静态层/足迹点 DPR 感知烘焙；门内 `qputenv("LA_HIDPI_DPR","2")` 模拟 200% 显示器，与 offscreen 平台 `devicePixelRatio` 不稳定解耦 → 可复现；`LA_HIDPI_QA_FORCE_LQ=1` 反例必红（非空心）。落 full 层（`measuredMs=762`）。

### 2.4 全循环编排器 `iterate.ps1`（把整条 SOP 一键跑完）

`qa_runner.ps1`（§2.3）只跑门禁；`iterate.ps1` 把「**构建 → 跑门禁 → 出报告**」整条 SOP 固化成一键脚本，是「下一代迭代指导」的完整体。

**用法**：
```powershell
cd D:\Test\workbuddy\2026-09-18-09-00-13\native
powershell -ExecutionPolicy Bypass -File .\iterate.ps1            # 默认：构建 + 全部门禁 + 报告
powershell -ExecutionPolicy Bypass -File .\iterate.ps1 -NoBuild   # 跳过构建（用已有 exe）
powershell -ExecutionPolicy Bypass -File .\iterate.ps1 -Only LA_GEO_SMOKE
powershell -ExecutionPolicy Bypass -File .\iterate.ps1 -Package    # 绿后自动 release.ps1 打包
powershell -ExecutionPolicy Bypass -File .\iterate.ps1 -NoBuild -Tier fast   # 只跑 PR 层
```

**报告（2.8.0 起）**：Markdown 头部含 `Gate tier:` 与 `Wall clock:`，门表新增 `ms` 列 —— 读者能一眼区分 fast 报告与全量报告。

**行为**：
1. **构建**（默认开，`-NoBuild` 跳过）：`cmake --build build --target LightAlbum -j 8`，失败即 `NO-GO` 中止（不误导用旧 exe 跑门禁）。
2. **跑门禁**：调用 `qa_runner.ps1`，后者额外写一份**机器可读 JSON 结果**（`$env:TEMP/qa_client/qa_result.json`，含每门 `name/mark/detail` + 汇总），编排器读它生成报告。
3. **出报告**：Markdown 报告（默认写 `$env:TEMP/LightAlbum_qa_<ts>.md`，含 Summary 表 + 每门结果/明细 + 红门专节），并打印控制台 `=== ITERATION VERDICT: GO/NO-GO ===`。
4. **可选打包**（`-Package`）：仅当 `GO` 时调 `release.ps1`，并传 `-SkipGate`（因 `iterate` 已验证 `GO`，避免门禁集重复跑两遍）。注意：单独直接跑 `release.ps1` 仍会把「全部门禁绿」作为**硬打包前置卡点**（见 §2.5），从机制上杜绝带病 exe 发布。

**判定**：构建失败 或 任一红门 → `NO-GO`、退出码 1（CI 可用 `if (!$LASTEXITCODE)`）；否则 `GO`、退出码 0。

**为什么用 JSON 而非捕获 stdout**：`qa_runner` 用 `Write-Host` 输出，而 PS 5.1 下 `-File` 子进程的 `Write-Host`（信息流 6）**不可被 `*> / 2>&1 6>&1` 等流重定向捕获**（实测抓到 0 行）。故 runner 落盘 JSON、编排器读文件，彻底解耦。

> 版本号 / CHANGELOG / 提交仍按 §6 CheckList 手工做（SemVer 决策需人拍板，编排器不自动 bump）。

### 2.5 两层防护：发布前卡点 + 提交钩子 + CI（「下一代迭代指导」闭环）

门禁不再只是「人记得跑」，而是**结构性强制**，红门在任何出口都被挡回。

**关键环境约束（实测，务必先读）**：门禁运行器 `qa_runner.ps1` 依赖**真实控制台**才能让原生 exe 自退——`stdout` 被重定向（管道/文件，如 git 钩子被 git 接管输出、CI 之外的重定向）时，exe 不会自退，会卡到每门 25s 超时（全 25 门 ≈ 10 分钟）或直接 `rc=-1` 无输出。故「能否真正跑门禁」取决于**调用方是否持有控制台**。

**① 发布前硬卡点（`release.ps1` 内置，可靠）**
- `release.ps1` 在打包前自动跑 `qa_runner.ps1` 全部门禁（要求交互式控制台）；任一红门即 `throw` 中止打包，并打印红门清单。
- 若 `release.ps1` 自身 stdout 被重定向（`> log`），为免 8 分钟卡死，门禁**跳过并告警**（在交互式控制台跑即可）。
- 紧急绕过：`powershell -File release.ps1 -SkipGate`（仅限已知安全场景）。
- `iterate.ps1 -Package` 已验证 `GO`，故传 `-SkipGate` 给 `release.ps1`，不重复跑门禁。

**② 提交钩子（git pre-commit，最佳努力 + 绝不误挡）**
- 逻辑：`native/hooks/pre-commit.ps1`（版本受控）。仅当**暂存区含 native 源码变更**（`native/src/`、`CMakeLists.txt`、`resources/`、`data/`）时才介入；纯文档提交直接跳过。
- **控制台判定**：钩子检测 `[Console]::IsOutputRedirected`。git 接管钩子输出（管道）→ 判定为重定向 → **快速跳过并告警**（约 0.5s，绝不卡 8 分钟、绝不误挡）；在控制台手动跑钩子时（有控制台）才真实跑门禁、红门即挡回。
- 跑门禁失败（运行器无输出）→ **放行并告警**（fail-open），绝不因工具抖动锁死每个 native 提交。
- 安装（二选一，钩子文件 Git 不跟踪，需手动装一次）：
  ```sh
  cp native/hooks/pre-commit .git/hooks/pre-commit        # 直接装
  # 或： git config core.hooksPath native/hooks            # 指向受控目录（pre-commit 即为 shim）
  ```
- 钩子 `.ps1` 故意**纯 ASCII**：PS 5.1 把无 BOM 的 UTF-8 `.ps1` 当 GBK 解析，中文串会报「字符串缺少终止符」导致钩子整体失效（同 §2.3 第 2 条）。

**③ CI 模板（`.github/workflows/qa.yml`，可靠自动门禁，已按本机工具链校准）**
- Windows runner：仅当 native 源码变更时触发 → aqtinstall 装 Qt6.8.3+MinGW（gcc 13.1，**与本机 winlibs GCC 13.1 ABI 对齐**）→ 新增「Add MinGW to PATH」步把 `C:/Qt/Tools/mingw1310_64/bin` 加入 PATH（否则 `cmake --build` 的 MinGW Makefiles 找不到 `mingw32-make`）→ 构建 → `iterate.ps1 -NoBuild` 跑门禁 → 红门即 job 失败。
- `iterate.ps1` / `qa_runner.ps1` 的 exe 路径与 cmake 已改为**自动解析**（`$PSScriptRoot` 相对 / PATH 检测），**不再硬编码用户专属路径**，同一套脚本本地与 CI 通用；`release.ps1` 的 `windeployqt` 亦自动探测（本地 `D:/qt` / CI `C:/Qt`）。
- CI agent 持有控制台（输出被捕获但进程有控制台），`iterate.ps1` 实测在该形态下稳定出 `GO`（PASS=18），**这是每 PR/推送最可靠的结构性门禁**。本地已用 `iterate.ps1 -NoBuild -Only LA_GEO_SMOKE` 验证便携解析 `GO`/PASS=1。

> 小结：可靠自动门禁 = **CI（iterate.ps1）** + **发布卡点（release.ps1）**；pre-commit 钩子为最佳努力提醒（有控制台才真挡，否则跳过快、告警、放行）。

## 5. 铁律（通用 7 条 + 地图 13 条事故，摘要）

**通用 7 条**（详见 `docs/标准化迭代指导书.md`）：
1. 单一真源（版本号/配置/变换）。
2. **绘制与命中同源**（同一变换数学，否则「看得见点不着」）。
3. 热路径不做 O(n) 重建/重算/逐条描边（静态 bake 一次、动态合批）。
4. **复用抽象要重审守卫**（新增层级时，所有 `level_==X` 分支必须逐一复查）。
5. 边界显式（零尺寸 QRectF 并集用 min/max；QPainter helper 一律 save/restore）。
6. 资源与状态分离（缓存失效入口唯一，改数据经 setter）。
7. 诚实数据/可观测（颜色校验必须实测不许猜；门禁断言单独成行）。

**地图 13 条事故铁律**（详见 `native/docs/迭代指导书.md`）：含「缓存失效入口唯一」「省环双层 JSON 格式」「中文 UTF-8 源码非 \x 转义」「缩放/平移后重置」「点空白按下待命原地松开才返回」等。

## 8. 迭代 4 实例（本轮 dogfooding）：修复 `LA_GEO_SMOKE` 红门

**背景**：DataV 34 省切换后，多边形主路径返回**中文省名**（北京市/广东省/辽宁省），`kCities` 英文兜底为残留债务；但 `runGeoSmoke` 测试期望仍是英文（`Beijing Municipality` 等），导致该门自切换后一直 RED——且因之前没跑 + Git Bash 吞输出，长期未被发现。

**取证**（PowerShell 跑 `LA_GEO_SMOKE`）：
```
GEO FAIL lat=39.90 lon=116.41 -> r=china pv=北京市 ct=北京   ← 实际中文，期望英文
GEO FAIL lat=23.13 lon=113.26 -> r=china pv=广东省 ct=广州
GEO FAIL lat=38.91 lon=121.61 -> r=china pv=辽宁省 ct=大连
```
