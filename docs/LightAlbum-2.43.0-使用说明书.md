# 光影集 LightAlbum 2.43.0 · 使用说明书

> **定位声明**：LightAlbum（native 版）是唯一正式分发形态——一个**零云端、纯本地**的 Windows 桌面照片管理客户端。发行物为单文件压缩包 `LightAlbum-2.43.0-win64.zip`，解压即用；旧 1.x Python 打包版本已全部停发并清理。
>
> **本版能力面**：**典藏（合集 / 展览史 / 安静下来的选题）** / **常设展 · 今日一展（馆长选题）与三手势** / 凝视策展序列（自动逐帧 + 呼吸驻足）+ 常驻键位带 / 前厅（今日回看 / 最新到馆） / 人物馆（一人一展室） / ⌘K 检索、跳转与**暂存为合集** / 展厅灯光（四灯可切 + 画布层随灯） / 图库浏览（年/月/季走索引） / 自动故事相册 / 相似照片去重 / 足迹地图（轨迹+热力+按年筛选+国家省市三级下钻） / 修图实验室（双引擎 + AI 消除真引擎 + 一键增强 13 算子） / AI 美图 / AI 场景分类 / 人脸识别与人物聚类（两遍精炼） / 隐私库（全链路一致过滤） / 中英双语 / 无障碍键盘操作 / 高 DPI 适配 / 统一动效引擎 / 设计语言 v2 / 原生导入器（含 iCloud 相册） / RAW 与视频 / HEIC·WebP 的 EXIF 容器抽取。所有处理均在你的电脑上完成，不向任何服务器发送照片或数据。
>
> **本版最重要的变化**：把上一版**写在界面上的承诺全部兑现**。2.42.0 让相册学会了主动开讲，但同时欠下三笔明写的债——「合集浏览下轮上线」「『别再这类』反悔入口下轮上线」「⌘K 暂存为合集仍是占位」。本版逐条还清：左侧导航多出第八区**典藏**（合集 / 展览史 / 安静下来的选题三个 tab，静音可**一键唤醒**），⌘K 的**暂存为合集真的能按下去了**，凝视模式补了**常驻键位带**并把每一枚键实装。同时按「界面上的每一句话都是承诺」把两处说过头的措辞改回实测口径（见 5.2、6 与 22 节）。
>
> 本版**没有新增任何运行时依赖**、**没有新增任何动效时长档位**（骨架呼吸、人物墙进人用的都是既有预设）、**没有新增任何用户可调环境变量**。上一版的全部 AI、修图与策展引擎能力**零改动**（12 个选题模板、打分公式、5–9 帧、7 天节流一行没动）。

## 1. 安装与启动

1. 解压 `LightAlbum-2.43.0-win64.zip` 到任意目录（无需安装器、无需管理员权限、无注册表写入）。
2. 双击 `LightAlbum.exe` 启动。窗口标题显示「光影集 LightAlbum 2.43.0」。
3. **AI 素材已在包内**：`3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录连同模型一起解压即可用，**无需任何下载或服务启动**。
4. **首次使用**：程序启动后自动读取默认库，落在**前厅**；若库为空，前厅会引导你导入第一场展览（顶栏「导入」亦可）。
5. **窗口最小尺寸是 960 × 640**（本版新钉的下界）。缩到这个宽度以下不会破版——图库与人物馆仍保持 **3 列**；再窄就不给缩了，因为「支持任意窄」实测不成立，程序不承诺做不到的事。

### 数据存放位置（默认，可用环境变量改）

| 内容 | 默认路径 | 环境变量覆盖 |
|---|---|---|
| 照片库（SQLite） | `D:\lightalbum\library.db` | `LA_DB` |
| 缩略图缓存 | `D:\lightalbum\thumbs\` | `LA_THUMPS` |

- 这两个路径与旧 1.x 版本**完全兼容**：已有库直接被读取，缩略图缓存互相命中，无需迁移。
- 若默认盘符不存在，可用环境变量指向任意位置，例如（CMD）：
  `set LA_DB=E:\photo\library.db` 后再启动。

### 本版给库文件加了什么

上一版补的四张表（`exhibits` / `albums` / `album_items` / `template_mutes`）本版**沿用不改**。本版在照片表上**幂等地补三列 + 一个月年索引**，并**一次性回填**：

| 加的东西 | 是什么 |
|---|---|
| `shot_ts` | 拍摄时刻（epoch 秒）。解不出日期 = `0`，不是 NULL |
| `shot_year` | 拍摄年份（与界面显示的年份同源）；无 EXIF 年份 = `0` |
| `shot_month` | 拍摄月份 `1..12`；解不出日期 = `0` |
| `idx_photos_year_month` | 建在 `(shot_year, shot_month)` 上的索引 |
| `meta` 表 | 只用来记一条 `ex_cols_backfill` 标记，保证回填**只跑一次** |

三条硬口径，都写明了为什么：

- **回填 fail-open**：任何一步失败都静默跳过——老库照旧能打开、照旧能用，只是查询退回全量扫描。绝不因为补索引而让库打不开。
- **回填读的是库里已有的 EXIF JSON**，不重新解码任何照片文件；单行失败只少回填那一行，不阻断启动。
- **只 ADD COLUMN / CREATE INDEX，零 DROP**：照片、标注、评分、私密标记一律不动。

另外提醒一个本版仍在用的字段语义：`seen_at` 是**扫描入库时间**，不是拍摄时间。界面上「新入藏」「搁了一年多」这类选题说的是入库时间，程序不会把它说成「拍摄于」。

## 2. 主界面

左侧图标栏**八区**，分三组（比上一版多第八区「典藏」）：

| 分组 | 页 |
|---|---|
| 浏览 | **前厅** / **足迹** / **图库** / **典藏** |
| 人物·修图 | **人物馆** / **修图** |
| 工具 | **日志** / **关于** |

顶栏（在非前厅页显示）从左到右：页面标题、**💡 展厅灯光**（点开选四灯，见第 15 节）、**🔍 检索**（点开 ⌘K 面板，等同 `Ctrl+K`）、**导入**下拉、**隐私库锁**。

- **前厅零 chrome**：前厅页隐藏顶栏与控制簇（纯沉浸），只保留左侧全局导航。
- **典藏页标题不压顶栏**：本版把「给顶栏让位」这条规则补给了典藏页（此前它漏了，标题与顶栏重叠）——八区现在全部按同一规则让位。
- 顶栏**悬浮自动隐藏**：向下滚动时收起，鼠标移回顶部或滚回顶端时落下。
- 页面切换与局部反馈动效由统一动效引擎驱动（见第 20 节）。

## 3. 导入照片（原生导入器）

点击顶栏「**导入**」下拉，两个入口：

- **导入目录**：选择任意照片根目录（子目录递归扫描；`相机原始/缓存/回收站` 等辅助目录自动跳过）。
- **导入 iCloud 相册**：自动探测本机 iCloud 照片目录（`%USERPROFILE%\Pictures\iCloud Photos\Photos` 等三个候选路径），**空目录会被拒绝**以免误报「已找到」。

扫描在后台线程进行，不卡界面；可随时取消。完成后弹出汇总（新增/已存在/跳过）。

导入器行为细节：

- 读取每张照片的 **EXIF**（拍摄时间、相机、镜头、焦距、光圈、快门、ISO、GPS 坐标、方向等）——**缺失项如实留空**，显示为 `—`，绝不编造。
- 每次导入都会写下入库时间（`seen_at`），策展引擎读它，用于「新入藏」「搁了一年多」这类选题。
- **本版新增**：同一趟扫描还会把拍摄时间落进 `shot_ts / shot_year / shot_month` 三列，供图库的年/月/季筛选走索引（第 8 节）。

## 4. 前厅（今日回看与最新到馆）

进门第一屏，三块墙：

- **今日一展 · 馆长选题**——有展时它是墙上的第一张卡，采用「开馆」高度层（金描边 + 内发光）。
- **今日展（往年今日）**：优先取「今年的今天」，不足 3 张逐级回退到**同月**、再**同季**；实在没有就安静显示「**今日无展 · 明日再会**」。**绝不拿别的照片凑数。**
- **最新到馆**：按入库时间倒序的最新一批。

**生成期骨架（本版新增）**：当程序正在为本机选展时，「今日一展」那个槽位不是空白、也不是转圈图标，而是一张同尺寸、同呼吸档的骨架卡，中间写着「**正在为本机选展…**」。它只说正在做什么，不预支结果；卡塌下去也不会带走旁边两块墙——**等待期间其余内容照常可看**。选展算完，骨架原地换成真展卡。

前厅隐藏顶栏，但左侧导航、`Ctrl+K`、灯光与隐私锁仍然可用。锁定状态下私密照片不会出现在任何一块墙上。

## 5. 常设展 · 今日一展与三手势

### 5.1 一版展是怎么来的

程序在**启动时**与**你回到前厅时**各看一眼：距上一版成功生成**超过 7 天**才新开一版。

> 这不是定时器。没有常驻后台、没有 03:00 准点跑批——「每周」是**懒生成 + 7 天节流**的结果，机器不开就不会生成，也不会有任何进程在后台待着。

生成过程（**冷库门槛**：库里少于 50 张照片时不成展；50–199 张只用两枚低门槛模板「新入藏 / 搁了一年多」；200 张起 12 个模板全开）：

1. **候选池**：全库照片，剔除**私密照片**（隐私库锁定时）与**近 4 周内已展出过**的照片。
2. **按库温放行 12 个选题模板各出一题**（见 5.3），每题给出自己的话题键。
3. **打分**：`新鲜度 − 重复度`。**不做偏好学习**——你收藏了什么、看过哪些展，**不影响**选题分数（这是有意的取舍，见 5.4）。
4. **频控**：依次过「模板是否被你静音」「本周是否已展过一场」「同一个人 60 天内是否展过」。
5. **裁展**：把选中的帧**目标裁到 5–9 张**（候选比 5 还少就如实给更少，**不拿别的照片凑数**），用相似指纹去掉连拍冗余，再按**画质分**排序——画质分只在**展内帧**上算，不会拿去扫全库。
6. **定展名**：**只有裁完帧之后**展名才会产生，名字里的张数就是屏上真实帧数（「今年 · 7 张」= 7 帧，不是候选有 7 张）。
7. 结果回到主线程写库，前厅墙面重挂。生成期间界面不冻结。

任何一步凑不出可展的帧，就**整卡不出现**（不是渲染一张空壳卡），并在引擎内部如实记下跳过原因。

> 本节口径与上一版**逐字相同**——本版一个模板、一个阈值都没动。

### 5.2 三种手势

卡上三个按钮，按下即刻落库，屏幕下方浮出回执。**本版三条回执全部改写**：上一版它们诚实地写着「下轮上线」，本版入口真做好了，回执就指回入口。

| 手势 | 做什么 | 回执说什么 |
|---|---|---|
| **收进合集** | 以展名为名建一个**永久合集**，把这一展的帧（含顺序）写进去；并把这一展标为「保留」 | 「已把《…》的 N 张存为永久合集，**可在典藏里再看**。」失败时是「没能收进合集，库里没多出一份空壳。」 |
| **换一展** | 记下「换展」意图，并**立刻**新开一版 | 「已换一展。」若确实没有更多可展的照片：「暂无更多可展的照片，先补几张进来。」 |
| **别再这类** | **永久静音该模板**——这一展当场撤下，以后自动推送也不再出这类题 | 「这类展已安静下来。**可在典藏 · 安静下来的选题里唤醒**。」 |

关于「换一展」的口径：

- 你按下按钮是**显式动作**，所以它**绕开 7 天节流**，并且**只放开「本周 ≤1」这一条腿**——模板静音、同人 60 天冷却**照旧生效**。
- 「换一展」后没有可展内容时，回执会**如实说没有**，不会假装换了。
- 点了「换一展」之后，墙上会先进入**生成期骨架**（第 4 节），算完才换新展——等待看得见，不是按下去没反应。

关于「别再这类」：静音写库成功后才会报「已安静下来」；**没落成就不许报成功**。撤下这一展同样是立刻新开一版，且新选的展必然不含被静音的那类题。

**回执的措辞纪律**：界面上写出来的每一句都是承诺。上一版合集的数据已落库但没有页面列出，所以回执只能写「下轮上线」；本版典藏页上线了，回执才允许写「可在典藏里再看」。**入口不在就不许写入口**——这条有门禁的反例臂守着（见附录 A）。

### 5.3 12 个选题模板与展名

展名由模板 + **真实展内张数**拼成，中英文都有译文。本版实际口径（与上一版相同）：

| 展名 | 这一版真的在选什么 | 需要什么前置数据 |
|---|---|---|
| 今年 · N 张 | 今年内拍的照片 | 拍摄日期（EXIF） |
| 旧识 · N 张 | 某一位人物的照片 | 已跑过「识别人物」 |
| 搁了一年多 · N 张 | 入库超过 1 年仍没被展过的 | 入库时间 |
| 一城 · N 张 | 同一城市的照片 | GPS + 离线逆地理编码 |
| 同一门类 · N 张 | 数量最多的那一个场景门类 | 已跑过「AI 分类」 |
| 黑白之间 · N 张 | 门类为「黑白」的照片 | 已跑过「AI 分类」 |
| 连拍那天 · N 张 | 同一天 ≥3 帧的日子 | 拍摄日期 |
| 在路上 · N 张 | 同城且跨 ≥2 天 | GPS |
| 那年今日 · N 张 | **仅固定公历节日**：元旦 / 劳动节 / 国庆 / 圣诞 | 拍摄日期 |
| 新入藏 · N 张 | 最近 14 天入库的 | 入库时间 |
| 夜色与远山 · N 张 | 门类为「夜景·星空」或「风光」 | 已跑过「AI 分类」 |
| 搁下两年 · N 张 | 入库超过 2 年的陈帧（方向 = 可退藏） | 入库时间 |

四处展名相对原设计名做了降级改名（主色聚类未接、轨迹连续段未接、不做「N 年前的同月日」对照、不宣称能一键退藏），理由与上一版相同：**名字不许承诺数据没做的事，也不许承诺界面没给的按钮**。农历节日不做。

**本版新增的一处**：典藏页的「安静下来的选题」列表显示的就是这张表里的**可读名**（「今年」「旧识」…），不是内部 token。对不上表的 token **如实显示原 token，不冒充某一类展**。

### 5.4 本版明确不做的

- **偏好学习**：收藏明细与展出历史不参与打分（代码里这一项权重字面为 0，并有门禁守着它不许被接上）。
- **真实定时推送**：见 5.1。
- **废片巡检界面**：引擎侧的批量巡检函数已就绪（连拍冗余 + 糊图 + 陈旧帧三规则，RAW/视频按既有铁律豁免），但**没有任何页面上它**。它**永不删除**任何文件，这一点由门禁断言守着。
- **连续三次「换一展」后的隐式降权**：只记意图，不改变打分（留后）。

上一版列在这里的「合集浏览页」「『别再这类』反悔 UI」两条，**本版已实现**，移入第 6 节。

## 6. 典藏（合集 / 展览史 / 安静下来的选题）——本版新增

左侧第八区。这一页是策展系统的**账本**：上一版说「记录都留在这里」但没有地方看，本版补上。

页面三个 tab，共用同一套行卡片语言（56×56 封面 + 标题 + 元信息行）。

### 6.1 tab 一 · 合集

- **一条 = 一次「收进合集」或一次「⌘K 暂存」**，按创建时间倒序。
- 行上显示：合集名 · 「N 张」 · 来源（**「策展收入」**=从前厅展卡收进来的 / **「检索收入」**=从 ⌘K 暂存进来的） · 创建日期。
- **锁定状态下报的是「可见」张数**：合集里若有私密照片，隐私锁定时你看到的数字就是滤掉私密之后的计数，不是库里的总数。**这一条只对合集生效**——展览史行报的是当初真实的展内帧数，那是历史事实，不该随今天的锁状态变化（两者的取舍不同，见第 16 节）。
- **双击一行**（键盘：方向键选中后按 Enter）**= 回放**：进入凝视档，帧序 = 你收藏时的顺序，`←`/`→` 就在合集内走。回放**不自动逐帧**——那是「今日一展」专有的策展序列语义。

空态：「**还没有合集**」——「在前厅按『收进合集』，或在 ⌘K 里勾选照片后按『暂存为合集』。」

### 6.2 tab 二 · 展览史

- **一条 = 一版生成过的展**，按生成时间倒序。
- 行上显示：展名（历史展名**按当时存下的原样显示**，不去"修正"它；库里没名字的老行显示「未命名展」） · 小记（有则显示） · 生成日期 · 「N 帧」 · 反馈徽标（**「已收进」/「已换走」/「已静音」**）。
- **双击同样进凝视档回放**这一展的帧。

空态：「**还没有展览**」——「前厅要距上一版超过 7 天才会自动再挑一展（重开应用时生效）；按『换一展』可随时换，记录都留在这里。」

> 这句文案为什么这么长，本身就是一条门禁（见附录 A 的 C8）：上一版这里写的是「前厅**每天**会挑一展」，而引擎实测节流窗是**严格超过 7 天**、且非显式动作的调用点只有冷启动一处（**没有定时器**）。天天打开应用也不会天天换展。文案说错了就是承诺说错了，所以本版把文案与引擎常量钉在同一条断言上——**改回「每天」会变红，把节流改成按天也会变红**。

### 6.3 tab 三 · 安静下来的选题

- **一条 = 一个被「别再这类」静音掉的模板**，按静音到期时间倒序。
- 行上显示：模板可读名（见 5.3） · 「**永久安静**」（本版唯一会写入的形态）或「安静至 <日期>」 · 右侧「**唤醒**」按钮。
- 点「**唤醒**」= 删掉这条静音记录，**并且立刻强制新开一版展**（走同一条生成期骨架）。也就是说反悔不需要等下一次启动。
- 唤醒没落库就不会刷新列表，也不承诺「已唤醒」。

空态：「**没有被静音的选题**」——「在前厅按『别再这类』，会让这类安静下来。」

### 6.4 典藏的数据边界（如实说）

- 典藏页**只读库**，所有写操作（建合集、静音、唤醒）都下单给同一个策展编排器，界面不直接碰 SQLite。
- 合集与展览史**不修改、不删除任何照片文件**；回放顺序读的是库里的顺序列。
- 私密照片在典藏里同样不显示缩略图内容；合集计数按可见性重算，展览史帧数不重算（理由见 6.1）。

## 7. 凝视模式（沉浸看展 · 含策展序列与键位表）

把「一张一张翻」变成「站在画前」。画面是**无边框全屏 + 悬停雾条**：平时画面干净，鼠标动一下才浮出操作；主色调**实时取自当前照片**（缩略图中心加权中位数饱和色）成为一圈环境光晕——照片色彩冷时自动改用当前**展厅灯**的辅助色，不会糊成一块。翻页即换展：上一张淡出、下一张携光入位，同屏最多两张，**任何输入都能打断**。

### 7.1 进入方式与档位（本版逐条实测并订正）

凝视档（Gaze）与浏览档（Browse）是同一盏灯箱的两个档位，**入口不同、档位不同**：

| 你在哪里 | 手势 | 打开的是 |
|---|---|---|
| 前厅 · 今日墙 | 单击一张 | **凝视档** |
| 前厅 · 最新到馆 | 单击一张 | 浏览档（可按空格转凝视） |
| **今日一展卡的主图** | 单击 | **凝视档 + 策展序列**（自动逐帧，见 7.2） |
| 人物馆 · 展室 | 单击一张 | **凝视档**，作用域 = 那一间展室 |
| ⌘K · 检索即凝视 | Enter | **凝视档**，作用域 = 检索可见集 |
| ⌘K · 回看今天 | Enter | **凝视档**，作用域 = 今日池 |
| **典藏 · 合集 / 展览史** | 双击（键盘 Enter） | **凝视档**，作用域 = 那一合集 / 那一展 |
| 图库 / 足迹 | **单击**一张 | **浏览档**（本版订正：不是双击，也不直接进凝视档） |
| 任意照片 | 按 **空格** | 浏览档 → 凝视档 |

> **两条对上一版说明书的订正**（代码行为没变，是上一版手册写错了）：① 图库与足迹是**单击**打开，不是双击；② 从图库打开的是**浏览档**灯箱，凝视档要按空格或从上面标「凝视档」的入口进去。上一版写「图库双击进入凝视模式」把两件事说成了一件。

### 7.2 策展序列（从今日一展卡进入）

- **自动逐帧**：帧序 = 展帧序（画质最高的帧先出，即卡上的主图），每张驻足 **2400 毫秒**（来自统一动效引擎的既有预设档位，界面上不写死毫秒，也不可调节）。
- **展名小记字幕**：底栏在展期间显示**展名**（有「小记」时以 `展名 · 小记` 形式显示）。
- **随手可退**：见 7.3 的「不打断」白名单之外，**任意按键**、或画面/窗口上的**任意点击**，都等于「你把控制权拿回来了」——立即退展，停止自动逐帧，字幕交还照片自己的地点·日期·器材，`←`/`→` 回到手动翻图语义。
- **退展不留残影**：退出后底栏绝不残留上一展的展名。
- **展帧不在库里就不接管**：如果这一展的帧一张都不在库中，程序不开序列、不假装开展。
- **表态即驻足**：在序列里按表态键，自动逐帧会**冻结 3 秒**（撤销窗口开着时帧一滑走，「再按同键撤销」就没对象了），提示条收起后自动解冻。

### 7.3 键位表（本版常驻显示，逐键实测）

底栏右下角常驻一行键位带：**`← → 翻｜空格 凝视｜Enter 收藏｜Esc 退出`**。表里写的每一枚键都在代码里实装，并由门禁逐键验过（不是「画上去的说明」）。

| 键 | 做什么 | 会写库吗 | 会打断策展序列吗 |
|---|---|---|---|
| `←` / `→` | 在当前作用域内翻图 | 否 | **会**（等于你拿回控制权） |
| `空格` | 浏览档 → 凝视档；已在凝视档则不动作 | 否 | **不会**（空格是「看得更近」，不是夺权） |
| `S` | 喜欢 | 是，按下即写 | **不会** |
| `Enter` | 收藏（与 `S` 同义） | 是，按下即写 | **不会** |
| `A` 或 `Delete` | 略过 | 是，按下即写 | **不会** |
| `L` | **封存**（底栏回执用这个词，不叫「锁定」） | 是，按下即写 | **不会** |
| 同键再按一次 | 撤销上一次表态（3 秒提示条内有效），底栏报「已撤销」 | 是（清空该标记） | 不会 |
| `Esc` | 退出灯箱 | 否 | （随窗口一起退出） |
| 其余任意键 / 任意点击 | — | 否 | **会**，立即退展 |

- 表态写的是标记列，与图库「相似照片去重」里那个「标记其余为待删」按钮写的是**同一列同一套数据**（`like` / `skip` / `lock`，空 = 无），改一处处处一致；**不动照片文件**。
- **这个标记本版被谁读，逐处对过**：写进库、再按同键可撤销，这是它的全部承诺。**图库网格里不显示它**（没有徽章）；**策展选题也不读它**——引擎确实按 `tag:like` / `tag:skip` / `tag:lock` 建了桶，但**12 个模板没有一个取 `tag:` 键**（`CurateEngine.cpp` 里 `tag:` 只出现在写入处，12 个 `case` 只筛 `cat:` / `city:` / `person:` / `y:` 等）。所以标过的照片**本版不会因此更容易或更不容易进展**，这正是 5.4 节「本版不做偏好学习」的另一面。登记在 22 节，不当缺陷藏起来。
- `L` 的「封存」**不是删除保护**：本版**没有任何删除照片文件的路径**（第 21 节逐条列过程序往磁盘写什么，其中不含删除原片），所以没有「误删」可防。旧手册把它写成「锁定（防误删）」是把想象写进了语义，本版订正为程序自己的用词「**封存**」。
- **一处用词不齐（本版登记未改）**：键位带写「Enter **收藏**」，按下后回执却写「已标记 **喜欢**」——同一个动作的两个名字。代码里 `Enter` 与 `S` 都走 `mark=like`，行为一致，只有措辞分家。改它要同时动常驻串、`.ts`/`.qm` 与 `LA_I18N_QA` 的对照腿，收口期不做第 13 处代码改动，**登记为下一轮的文案收口项**（见第 22 节）。
- 「不打断」白名单本版从四枚扩到六枚：`S` / `A` / `Delete` / `L` / `Enter` / `空格`。上一版手册写的是「除 S/A/Delete/L 四个表态键之外的任意按键都退展」，而本版 `Enter` 与 `空格` 也是既定手势，把它们算作夺权就没法边看边标了。
- 私密过滤在凝视模式下同样生效。
- 键位带本身不可点击、不进 Tab 焦点序（它是说明，不是控件）。

## 8. 图库（浏览与筛选）

- 网格浏览、按年/月/人物/门类/地点筛选、评分与标记、批量操作。
- 单击任意照片打开浏览档灯箱（见 7.1）；按空格转凝视。
- 隐私锁定状态下私密照片不出现在网格、筛选计数与聚类里。
- **列数是本版重新算的**：网格列数收成一个纯算术函数（卡宽 + 间隙估值当栅距），图库与人物馆共用同一真源。**960 px 宽 = 3 列，1440 = 5 列，2560 仍封顶 5 列**——上一版死写 4 列，在最小窗宽下会挤成 6 列破版。
- **年/月/季筛选走索引（本版性能改动）**：按年、按月、按季的粗筛交给库里的 `idx_photos_year_month`，**日号一级的筛选仍在内存里做**。两条腿都有门禁守着：一条比对「索引结果 == 原内存谓词结果」（换了快路但不许换答案），一条 `EXPLAIN` 断言查询真的用上了索引。
- **空态（本版补齐，三态各不相同）**：
  - 「**馆内还没有照片。**」——「回到前厅导入一个目录，这里就会挂满你的作品。」
  - 「**这里没有符合条件的照片。**」——「清掉筛选，或按 ⌘K 换个说法再找。」（有筛选条件时空网格）
  - 「**当前没有可显示的照片。**」——「其中可能有私密照片：点顶栏的「隐私库」解锁后就能看到。」（无筛选条件但空）

### 8.1 相似照片去重

图库聚类条上的「相似照片」沿用原选片页的引擎（感知哈希 + 汉明距离），**逐张比对全部在本机完成**；私密照片不参与比对。

对话框里那枚珊瑚描边的「**标记其余为待删**」按钮，写的是 `mark=skip`——**与凝视档的「略过」同一列同一个值**。**它不删任何文件**：本版没有任何删除照片文件的路径（见第 21 节），「待删」是**标记名**，不是动作，也不会有第二次确认弹出来。点完这组就从列表收起，照片还在原处。这个措辞是选片页时代留下的，本版**登记为文案欠账**（见第 22 节），不做代码改动。

### 8.2 自动故事相册

按「地点 + 时间窗口」启发式分组，是**呈现视图**，不写库、不改文件。

## 9. 人物馆（一人一展室）

把一个「人」当作一间**展室**：展室名是人物名，墙上是他的照片。

- **展签卡**：一位人物一张装裱卡（白色卡纸 + 投影，悬停镀金），显示姓名、照片数与时间跨度（如 `2019–2024`）。
- **展室视图**：点开后按**年份分桶横向串联**，照片按时间铺陈，单击任意一张进入凝视档（作用域 = 这一间）。
- **进人动效（本版新增）**：展室打开时卡片按既有 `kPushDoor` 预设**依次进人**，延迟用引擎的 stagger 起点函数算，页里不自建时序。本版**只做透明度入场**——位置/缩放不动。取舍写在这里：动效宪章希望入场带轻微位移，而位移会与网格布局的落位互相打架，宁可只做一半也不硬凑。
- 点展签右侧可**跳去图库按这个人筛选**（与图库人物条、⌘K 的人物词典共用同一套状态）。
- **空态**：还没识别过人物时显示「**馆内布展中**」，一键调用**识别人物**（第 18 节）。
- **隐私一致**：私密照片不会让一个人的展室凭空多出内容，也不会把只出现在私密照片里的人列进来。
- 「旧识 · N 张」这一选题用的就是人物馆的聚合结果；人物**以名字为键**，改名会让历史展的「同人 60 天冷却」判定断档——这是已接受的脆弱性，如实记在这里。

## 11. 修图实验室（核心）

`修图` 页，全部处理零云端：

- **手动滑杆 12 项**：曝光 / 亮度 / 对比 / 清晰 / 自然饱和 / 饱和 / 色温 / 色调 / 锐化 / 高光 / 阴影 / 暗角；
- **16 个预设** + 「智能增强」（本地规则引擎，无外部依赖）；
- **★一键增强 · 13 算子**：影调 / 人像 / 校正三组平铺在工具区，一次点击按序执行。全程**异步**（忙碌态、不冻结），每步走现有撤销/重做通道；导出时按整条序列在全分辨率重放，不是把预览小图放大。
  - **诚实反馈**：红眼修复的命中点数、肤色占比、水平校正的角度都会如实报出；判定为「无倾斜」的校正明确提示**不改动**。
- **撤销栈**：任一步可回退；
- **几何编辑**：旋转、翻转、拉直 ±10°、比例裁剪与交互裁剪；
- **画笔蒙版**：局部涂抹后色调只作用于涂抹区域；
- **对比视图**：左右分割线对比原图与修后；
- **导出副本**：预览所见即导出所得；
- **★AI 消除**：涂抹要移除的物体，本地 LaMa 模型补全背景。执行器是**独立子进程**，零云端、崩溃只影响当次任务、自动重拉；推理在专属线程，**秒级计算期间界面完全不冻结**，可看到「处理中」状态并可取消。未随附模型时诚实提示「模型未就绪」，绝不假成功。
- **图像处理速度**：热点循环为**算子内按行/按瓦片并行**（可用 `LA_LUMEN_THREADS=1` 退回串行）。并行与串行结果**逐字节相等**。
- **画布颜色本版起跟着展厅灯走**（见第 15 节）。
- **空态（本版新增）**：「**还没有选中的照片。**」——「在图库或典藏里双击一张，就能进这里修。」
  > 这句本版实测有两处不精确，留在这里如实记：① 图库是**单击**打开灯箱（不是双击）；② 从灯箱进修图还要点底栏的「修图台 →」，不是直接落进修图页。可达性没问题，措辞偏松，本版不改代码（收口期只动文档），登记在第 22 节。

## 14. ⌘K 检索与跳转

在任意页按 `Ctrl+K`（或点顶栏 🔍）唤出。用**一句人话**描述你要找的东西，面板把它拆成可点可改的「条件 chip」。

- **时间**：`去年` / `前年` / `今年` / `2021年` / `春天`（也认组合，如「去年秋天」）/ 月份 / `昨天` / `今天`。
- **人物**：直接写名字（前缀匹配）。名单来自人物馆的同一份聚合结果——**锁定态下不含只在私密照片里出现的人**。
- **地点**：省 / 市 / 大区名，取自库内实际出现的取值。
- **风格**：8 类场景标签的中文字面（人像 / 风光 / 夜景·星空 / 城市·建筑 / 微距·花卉 / 动物 / 美食 / 黑白）。
- **老能力保留**：标题、文件名、器材的包含匹配仍在，**零丢失**。
- **chip 可见即可纠**：点 chip 循环切换候选，`×` 移除。
- **面板会自己报词典现状**：四条例子胶囊分别是「时间 去年 · 今年 · 春天 · 六月」「人物 <库里真实前三个名字>」「地点 <库里真实前三个地名>」「风格 人像 · 风光 · 夜景·星空 · 黑白」。没跑过人脸识别时人物那条就写「**尚未识别**」，没 GPS 时地点那条写「**无地点元数据**」——**不拿假名字充数**。
- **听不懂时给可解析样例**：输入拆不出任何条件时，面板明写「**没听懂这个词。可以试：2019 / 夏天 / 去年**」，而不是静默给你全库。
- **动作行（本版三个真动作）**：
  - `Enter` / 「执行」：把条件袋交给图库筛选并跳页。
  - 「**检索即凝视**」：同样先落筛选，然后直接打开可见集第一张的凝视档（作用域 = 可见集）。
  - 「**暂存为合集**」：**本版从占位变成真能按**。它把**图库里当前勾选的照片**以你输入的那句话为名字建一个永久合集，来源标为 `检索收入`，落进典藏。落库成功回执与「收进合集」同一份真源（「已把《…》的 N 张存为永久合集，可在典藏里再看。」）。
    - **可用性只由一件事决定**：图库有没有勾选。空选时按钮**灰着**，tooltip 写「**先在结果里勾选照片**」；有勾选时 tooltip 变「**把勾选的照片存进典藏**」。
    - **名字取输入框当前文字**（去掉首尾空格）；名字为空则**不建空壳合集**。
    - **载荷在点击那一刻才取**，不是开面板时的快照——从开馆到你按下之间勾选变了，存下去的就是变后的集合。
    - 建好后典藏页立刻可见（同批刷新），不用重开。
- 面板本身沿用「开馆」高度层（与今日一展卡同一层）。
- 全程**本机零网络**：词典是内置的，照片不出机器。

上一版这里写的「`C`「暂存为合集」**仍是尚未上线的占位项**」本版作废——入口已上线，且不再绑 `C` 键，而是动作行上的一枚真按钮。

## 18. 本地 AI 引擎（随包独立子进程，**不需要启动任何服务**）

三个 AI 能力各自对应一个**随包的可执行文件**，由程序按需拉起为**子进程**，通过标准输入/输出传递帧消息（`READY` / `REQ` / `RES` / `ERR`）。

**没有 HTTP 服务、没有端口监听、没有需要你先双击的 `.bat`。**

| 能力 | 引擎 | 包内位置 | 模型文件（与 exe 同目录） |
|---|---|---|---|
| AI 消除 | `inpaint.exe` | `3rdparty/lama/bin/` | `lama.onnx`（LaMa，Apache-2.0） |
| AI 分类 | `clipinfer.exe` | `3rdparty/clip/bin/` | `clip_vit_b32_img.onnx`（CLIP ViT-B/32 视觉塔）+ `prompts.bin`（8 类提示词矩阵） |
| 识别人物 / 智能聚类 | `faceinfer.exe` | `3rdparty/face/bin/` | `detection.onnx`（SCRFD-10GF 检测）+ `recognition.onnx`（ArcFace w600k_r50 识别） |

三个引擎都依赖 **ONNX Runtime 1.19.2**（MIT，随包 `onnxruntime.dll`）。`faceinfer.exe` 另需 `Qt6Core/Qt6Gui` 与 MinGW 运行库，以及 **JPEG 解码插件** `3rdparty/face/bin/imageformats/qjpeg.dll`。

### 18.1 一次运算的时间花在哪里

- **首次拉起**要加载模型：人脸引擎实测 `READY` 约 **2.5 秒**，分类引擎实测在 **0.5–3.7 秒**摆动。程序给的等待预算分别为人脸 30 秒、分类 60 秒。
- 之后进程**常驻复用**，每张只需数百毫秒量级。
- 进程**保活、不因单张失败被杀**；取消只在批间/张间检查点被检查。
- **策展生成不用引擎**：它只读缩略图算相似指纹与画质分，**不为选题解码全库原片**，解码次数红线钉在「展内帧数」以内（≤9 次）。

### 18.2 引擎读的是哪份数据

- **人脸识别读原图的绝对路径**，由子进程自己从磁盘读；程序不复制原片、不改写原片。
- **场景分类读库内缩略图**。
- 两类都会**按 EXIF 方向摆正后再推理**。

### 18.3 出问题时你会看到什么

| 状态 | 你会看到 | 数据后果 |
|---|---|---|
| 引擎或模型文件缺失 | 点按钮弹出「**AI 引擎未就绪**（缺模型或引擎文件…）」，功能不启动 | 库完全不被触碰 |
| 引擎启动超时 / 崩溃 | 该轮如实报「中断（可能已部分写入）」，其余批次继续 | 已写入的部分保留，不写假标签 |
| 单张推理失败 | 该张被跳过（不标注），进度继续 | 该张保持未分类/未标注 |
| 你点取消 | 在下一次检查点停下来，已完成部分照常写回 | 不丢已完成结果 |
| 策展生成算不出可展的帧 | **前厅不出现今日一展卡**（不是空卡） | 库里不写空展 |

> 包内**没有** `fetch_ai.ps1`（它属于源码树的准备脚本）。发布包用户遇到「引擎未就绪」，正确处置是：**重新完整解压**，或用包内 `MANIFEST.txt` 逐文件 `Get-FileHash` 比对。

## 21. 隐私与数据安全

- 全部功能**零云端**：无遥测、无账号、无联网上传。
- **策展与典藏尤其如此**：选题、打分、裁展、生成展名、建合集、静音/唤醒全部是本地纯计算 + 本地 SQLite 写入，不产生任何网络请求。
- AI 分类与人脸推理**不经过任何 socket**，进程间只走标准输入/输出管道。
- 唯一仍会连接本机端口的是**可选的** Ollama 智能体（`127.0.0.1:11434`），且程序**只允许回环地址**。

- 修图、美图、分类均「调整参数 → 导出副本」，**不修改原片**；凝视模式的表态写的是标记列，不动文件。
- **本版新增的写操作只有三类**：一次「⌘K 暂存」（`albums` + `album_items`）、一次「唤醒」（删 `template_mutes` 一行）、启动时的一次时间列回填（改 `shot_*` 三列，不动任何用户内容）。**没有任何路径会删除照片文件**——废片巡检同样只打包、不删除（红线由门禁断言守着）。

> 本版**没有新增任何用户可调的环境变量**——7 天节流、每周 ≤1、60 天冷却、5–9 帧、960 最小窗宽、2400 ms 驻足这些口径都是代码内常量并有门禁守着，故意不开放为可调项（可调就会变成「文档里的第二个真源」）。

## 24. 故障排查

| 现象 | 处理 |
|---|---|
| 前厅没有「今日一展」卡 | 四种正常情况：① **库里少于 50 张照片**（冷库不成展，见 5.1）；② 50–199 张时只有两枚低门槛模板可用，两者都凑不出帧就没有展；③ 可用的模板都被静音了，或本周已展过一场且没有其他候选题；④ 候选帧全部已在近 4 周展出过。**不是加载失败**，也不会渲染一张空卡 |
| 前厅一直显示「正在为本机选展…」 | 正常——生成在后台线程跑。若长时间不结束，看日志页有无「中断（可能已部分写入）」；界面本身不会冻结 |
| 「收进合集」后找不到合集 | 去左侧第八区**典藏 · 合集**（本版已上线，无需重开，建完立即可见） |
| 典藏里合集显示的张数比我存的少 | **隐私锁定时按可见张数报数**（合集里有私密帧就被滤掉了）。解锁后回库内总数 |
| 点了「别再这类」想反悔 | 典藏 → **安静下来的选题** → 该行右侧「**唤醒**」。唤醒会立刻新开一版展 |
| 「安静下来的选题」tab 里有看不懂的英文单词 | 那是**没对上模板表的历史 token**，程序如实显示原 token 而不编名字。这类行唤醒同样有效 |
| 「换一展」点了没换 | 说明**确实没有别的可展内容**——回执会说「暂无更多可展的照片，先补几张进来」。注意模板静音与同人 60 天冷却对「换一展」同样生效（只有「本周已展过一场」这条被放开） |
| 明明每天打开，展览史里几天才一条 | **正常**。节流窗是「超过 7 天」，且自动重生成只发生在冷启动。想立刻换就按「换一展」 |
| 凝视序列自动翻到下一张，我想停下 | **按任意键**（`S`/`A`/`Delete`/`L`/`Enter`/`空格` 六枚之外）或**点一下画面**即可退展；之后 `←`/`→` 回到手动翻图 |
| 在凝视里按了 `S` 但画面没继续走 | **正常**——表态后自动逐帧冻结 3 秒（撤销窗口开着），提示条收起后继续 |
| 驻足太快 / 太慢，能不能调 | 固定 2400 ms（引擎预设档位），不提供滑杆 |
| ⌘K「暂存为合集」是灰的 | **图库没有勾选**（tooltip 会写「先在结果里勾选照片」）。先在结果里勾选；输入框也不能为空 |
| 按 Enter 建了合集但典藏里名字很怪 | 合集名 = **你输入框里的那句话**（本版没有另设命名框）。想改名等下一轮的收藏管理 |
| 图库按年筛选比预期慢 / 老库没有年份结果 | 年/月/季走 `shot_year/shot_month`。老库在启动时**一次性回填**；回填失败会静默退回全量扫描，功能仍可用（只是不加速） |
| 界面缩到很窄时只看到 3 列 | 设计如此。列数按窗口宽度算（960→3、1440→5），不是固定 4 列 |
| 英文界面看到 `curate.tmpl.*` 之类的键名 | **不应发生**——展名有门禁守着。若你看到，请报告（附截图与语言设置） |
| 竖拍的手机照片检不到脸 | 已按 EXIF 方向摆正后再检测。若库是在更旧版本上标注的，建议重跑一次「识别人物」 |
| **AI 分类 / 识别人物 提示「AI 引擎未就绪」** | **不需要启动服务**。确认包解压完整（见 18.3），可用 `MANIFEST.txt` 逐个 `Get-FileHash` 比对 |
| 文件明明都在，仍报「引擎未就绪」 | ① 该机没装 Visual C++ 2015–2022 可再分发库；② `3rdparty/face/bin/imageformats/` 被移走——此时 JPEG 一律读不进而 PNG 仍正常 |
| AI 消除提示「模型未就绪」 | 确认 `3rdparty/lama/bin/` 完整；缺失时相应功能诚实挂起，其余不受影响 |
| 玉照 / 素印灯下修图画布仍是黑的 | **本版已修**（画布四色随灯）。若在旧版遇到，升级到本版 |
| 前厅显示「今日无展 · 明日再会」 | **正常**——往年这一天确实没有可展照片（当日/同月都不足 3 张，同季也稀薄）。这是诚实空态 |
| 人物馆显示「馆内布展中」 | 还没识别过人物。点它跑一次「识别人物」即可 |
| 高分屏下界面发糊 | 确认未强制 `QT_SCALE_FACTOR`；程序按系统缩放渲染 |
