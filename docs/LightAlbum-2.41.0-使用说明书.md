# 光影集 LightAlbum 2.41.0 · 使用说明书

> **定位声明**：LightAlbum（native 版）是唯一正式分发形态——一个**零云端、纯本地**的 Windows 桌面照片管理客户端。发行物为单文件压缩包 `LightAlbum-2.41.0-win64.zip`，解压即用；旧 1.x Python 打包版本已全部停发并清理。
>
> **本版能力面**：**前厅（今日回看 / 最新到馆）** / **人物馆（一人一展室）** / **⌘K 检索与跳转** / **凝视模式（沉浸看展）** / **展厅灯光（四灯可切）** / 图库浏览 / 自动故事相册 / 相似照片去重 / 足迹地图（轨迹+热力+按年筛选+国家省市三级下钻）/ 修图实验室（双引擎 + AI 消除真引擎 + 一键增强 13 算子）/ AI 美图 / AI 场景分类 / 人脸识别与人物聚类（两遍精炼）/ 隐私库（全链路一致过滤）/ 中英双语 / 无障碍键盘操作 / 高 DPI 适配 / 统一动效引擎 / 设计语言 v2 / 原生导入器（含 iCloud 相册）/ RAW 与视频 / HEIC·WebP 的 EXIF 容器抽取。所有处理均在你的电脑上完成，不向任何服务器发送照片或数据。
>
> **本版最重要的变化**：界面从「一排工具页」换成了「一座场馆」。进门是**前厅**（往年今日 + 最新到馆），照片按下快门的人收进**人物馆**，看展改用**凝视模式**（全屏、无边框、一键表态），找照片直接按 **⌘K**（Ctrl+K）用一句话描述。同时把颜色收成一组可切换的**展厅灯光**——四套灯（夜展 / 玉照 / 素印 / 暮金），换灯只换表面与文字色，**不动版式**。
>
> 与之配套，原先的「首页」与「选片」两张页**已退役**（它们与前三页的信息高度重叠）。退役的只是页面：**相似照片去重移居图库聚类条**，它的引擎与隐私过滤一字未改；**「智能选片」整页不再提供**。既有照片库、标注、评分与私密标记**零影响**。
>
> 本版**没有新增任何运行时依赖**，压缩包体积与 2.40.0 基本持平。随包五组第三方运行时与模型沿用上一版：LibRaw（约 3.5 MB，LGPL/CDDL 双许可）、FFmpeg（约 200 MB，GPL-3.0）、AI 消除执行器（`inpaint.exe` + ONNX Runtime + LaMa 模型）、人脸引擎（`faceinfer.exe` + SCRFD / ArcFace）、场景分类引擎（`clipinfer.exe` + CLIP ViT-B/32 + 8 类提示词矩阵）。三组 AI 载荷的未压缩体积与压缩包字节数见 2.40.0 手册与包内 `MANIFEST.txt`，本版未改动。

## 1. 安装与启动

1. 解压 `LightAlbum-2.41.0-win64.zip` 到任意目录（无需安装器、无需管理员权限、无注册表写入）。
2. 双击 `LightAlbum.exe` 启动。窗口标题显示「光影集 LightAlbum 2.41.0」。
3. **AI 素材已在包内**：`3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录连同模型一起解压即可用，**无需任何下载或服务启动**。
4. **首次使用**：程序启动后自动读取默认库，落在**前厅**；若库为空，前厅会引导你导入第一场展览（顶栏「导入」亦可）。

### 数据存放位置（默认，可用环境变量改）

| 内容 | 默认路径 | 环境变量覆盖 |
|---|---|---|
| 照片库（SQLite） | `D:\lightalbum\library.db` | `LA_DB` |
| 缩略图缓存 | `D:\lightalbum\thumbs\` | `LA_THUMPS` |

- 这两个路径与旧 1.x 版本**完全兼容**：已有库直接被读取，缩略图缓存互相命中，无需迁移。
- 若默认盘符不存在，可用环境变量指向任意位置，例如（CMD）：
  `set LA_DB=E:\photo\library.db` 后再启动。

## 2. 主界面

左侧图标栏**七区**，分三组：

| 分组 | 页 |
|---|---|
| 浏览 | **前厅** / **足迹** / **图库** |
| 人物·修图 | **人物馆** / **修图** |
| 工具 | **日志** / **关于** |

顶栏（在非前厅页显示）从左到右：页面标题、**💡 展厅灯光**（点开选四灯，见第 12 节）、**🔍 检索**（点开 ⌘K 面板，等同 `Ctrl+K`）、**导入**下拉、**隐私库锁**。

- **前厅零 chrome**：前厅页隐藏顶栏与控制簇（纯沉浸），只保留左侧全局导航。
- 顶栏**悬浮自动隐藏**：向下滚动时收起，鼠标移回顶部或滚回顶端时落下。
- 页面切换与局部反馈动效由统一动效引擎驱动（见第 17 节）。

## 3. 导入照片（原生导入器）

点击顶栏「**导入**」下拉，两个入口：

- **导入目录**：选择任意照片根目录（子目录递归扫描；`相机原始/缓存/回收站` 等辅助目录自动跳过）。
- **导入 iCloud 相册**：自动探测本机 iCloud 照片目录（`%USERPROFILE%\Pictures\iCloud Photos\Photos` 等三个候选路径），**空目录会被拒绝**以免误报「已找到」。

扫描在后台线程进行，不卡界面；可随时取消。完成后弹出汇总（新增/已存在/跳过）。

导入器行为细节：

- 读取每张照片的 **EXIF**（拍摄时间、相机、镜头、焦距、光圈、快门、ISO、GPS 坐标、方向等）——**缺失项如实留空**，显示为 `—`，绝不编造。
- **EXIF 抽取覆盖 WebP**（RIFF 的 EXIF chunk）与 **HEIC**（ISOBMFF `meta/iinf/iloc` 最小解析），先剥出内层 TIFF 数据块再走与 JPEG 相同的解析器；**剥不出就退回文件系统修改时间**。诚实边界：兜底值**只填时间、不带来源标记**——界面与库里都看不出它是 EXIF 还是 mtime。
- 自动生成缩略图，缓存键与旧版共享（同一文件不会重复生成）。
- **增量安全**：重复导入同一目录时，未变化的文件直接跳过；删除照片的评分等元数据不会被覆盖。
- 云盘占位文件（OneDrive 等）会被识别并标记，不会当作有效照片。
- RAW 解码缩略图与 EXIF；视频入库并抽帧封面，与照片同为受支持格式。

## 4. 前厅（今日回看与最新到馆）

开馆首屏，回答两个最常被问的问题：**「今天有什么可看的」** 与 **「最近拍了什么」**。

- **今日展**：把**往年同一天**（月-日相同）的照片挑出来，排序优先贴近今年、同级按评分。候选不足 3 张时逐级放宽——同月 → 同季；实在没有就安静地显示「**今日无展 · 明日再会**」，**绝不拿别的照片凑数**。
- **最新到馆**：按**拍摄日期**倒序取最近的一批。注意措辞——数据库里没有「入库时间戳」这一列，所以这里说的是「最新拍到的」，不是「最新导入的」。
- 点任意一张进入**凝视模式**（第 10 节）；厅心另有「导入」入口，空库时直接引导你开第一场展览。
- **隐私一致**：私密照片在筛选阶段就被排除，不会出现在前厅的任何一栏。

## 5. 图库（浏览与筛选）

- 网格缩略图 + 底部**胶片条**快速切换；点击打开**灯箱**全屏查看，支持滚轮缩放（以鼠标为锚点）、拖移、适屏。
- **灯箱加载原图**：先秒出缩略图，后台渐进加载原图并淡入替换；加载失败诚实降级不黑屏。大库翻图定位走索引化路径。
- **多选**（Ctrl / Shift）与批量工具条（★评分 / 🔒私密 / 标记待删）。
- **检索入口已迁移**：2.41.0 起，顶栏的内嵌搜索框改为 **⌘K 面板**（第 11 节），语义更宽——既能按标题/文件名/器材找，也能按时间、人物、地点、风格找。`Ctrl+K` 可在任意页唤出。
- 大库下已做**窗口化虚拟化 + 两级缩略图缓存**，数千张照片滚动依旧流畅。
- **缩略图骨架屏**：未解码卡片显示 shimmer 骨架占位，解码完成平滑替换；缺画出稳定缺失态。动画尊重系统「减少动态效果」设置。

### 5.1 相似照片去重

图库聚类条上的「**相似照片**」按钮（原「选片」页的入口，2.41.0 起移居此处）：

- **MD5 完全重复 + 感知哈希（pHash）相似聚类**，结果按分组浏览；
- 可批量「标记待删」——**非破坏性**（只写标记，不动文件），可撤销；
- **隐私一致**：私密照片**在注入点就被排除**，不进入相似度分析输入集（锁定态、解锁态均过滤），不会被间接曝光。

### 5.2 自动故事相册

图库页顶部一条**故事条**，一键把照片组织成「可以讲述的瞬间」。完全在视图层聚合，**不写入照片库**——原始数据不受影响，关闭筛选即回完整图库。

- **按「地点 + 时间窗口」自动分组**：同一地点、拍摄间隔不超过阈值（默认 5 天）的连续照片归为一个故事；地点先取省市、再退回大区、最后「未知地点」兜底，绝不编造坐标归属。
- **人物圆形头像墙**：故事条左侧展示已识别人物的圆形头像，点击只看该人物照片。
- **守恒保证**：分组是纯函数计算，输入多少张输出还是多少张——任何照片都不会被悄悄丢弃（由自动化门禁断言）。
- **规模封顶**：故事条最多展示 60 个分组，保证界面永远流畅。
- **一键开关**：点击故事条开启/关闭故事筛选。

## 6. 人物馆（一人一展室）

把一个「人」当作一间**展室**：展室名是人物名，墙上是他的照片。

- **展签卡**：一位人物一张装裱卡（白色卡纸 + 投影，悬停镀金），显示姓名、照片数与时间跨度（如 `2019–2024`）。
- **展室视图**：点开后按**年份分桶横向串联**，照片按时间铺陈，点任意一张进入凝视模式。
- 点展签右侧可**跳去图库按这个人筛选**（与图库人物条、⌘K 的人物词典共用同一套状态，不会出现「两个筛选各说各话」）。
- **空态**：还没识别过人物时显示「**馆内布展中**」，一键调用**识别人物**（第 15 节）；术语沿用「识别人物」，与图库页按钮是同一个实现。
- **隐私一致**：私密照片不会让一个人的展室凭空多出内容，也不会把只出现在私密照片里的人列进来。
- 本版**不含**「周年展开关」与新的合并/拆分入口——合并与改名仍在图库的人物 chips 上右键完成（避免两处入口互相打架）。

## 7. 足迹（地图）

- **零外链地图**：世界地图与多国省多边形数据编在 exe 内，离线可用。
- **三级下钻**：世界 → 国家 → 省。有 GPS 的照片按真实坐标落点。
- **离线逆地理编码**：GPS 坐标归属到国家/省份（点内多边形计算 + 城市最近邻兜底）。
- **轨迹层 / 热力层 / 按年筛选**三种足迹视图随时切换。
- 诚实原则：落在覆盖范围之外的照片**留空不猜**。

## 8. 修图实验室（核心）

`修图` 页，全部处理零云端：

- **手动滑杆 12 项**：曝光 / 亮度 / 对比 / 清晰 / 自然饱和 / 饱和 / 色温 / 色调 / 锐化 / 高光 / 阴影 / 暗角；
- **16 个预设** + 「智能增强」（本地规则引擎，无外部依赖）；
- **★一键增强 · 13 算子**：影调 / 人像 / 校正三组平铺在工具区，一次点击按序执行。全程**异步**（忙碌态、不冻结），每步走现有撤销/重做通道；导出时按整条序列在全分辨率重放，不是把预览小图放大。
  - **诚实反馈**：红眼修复的命中点数、肤色占比、水平校正的角度都会如实报出；判定为「无倾斜」的校正明确提示**不改动**，不假装做了事。
- **撤销栈**：任一步可回退；
- **几何编辑**：旋转、翻转、拉直 ±10°、比例裁剪与交互裁剪；
- **画笔蒙版**：局部涂抹后色调只作用于涂抹区域；
- **对比视图**：左右分割线对比原图与修后；
- **导出副本**：预览所见即导出所得；
- **★AI 消除**：涂抹要移除的物体，本地 LaMa 模型补全背景。执行器是**独立子进程**（`inpaint.exe` + ONNX Runtime + 随包模型），零云端、崩溃只影响当次任务、自动重拉；推理在专属线程，**秒级计算期间界面完全不冻结**，可看到「处理中」状态并可取消。未随附模型时诚实提示「模型未就绪」，绝不假成功。
- **图像处理速度**：修图引擎的高斯模糊、色调映射、中值/平滑滤波、红眼与暗角、镜头校正等热点循环为**算子内按行/按瓦片并行**（可用 `LA_LUMEN_THREADS=1` 退回串行）。并行与串行结果**逐字节相等**（内存逐位比对，由门禁断言），像素输出语义零变化。
- **「AI 智能体」**（可选，见第 14 节）：本地大模型读测量值给出修图方案。

## 9. AI 美图

`美图` 页为风格化预设画廊：16 种风格卡片（含缩略图预览），点选套用 + 大图 before/after + 智能增强 + 导出副本。

## 10. 凝视模式（沉浸看展）

把「一张一张翻」变成「站在画前」。入口有三个：**前厅厅心**、**人物馆展室**、**图库双击**。

- **无边框全屏 + 悬停雾条**：平时画面干净，鼠标动一下才浮出操作；主色调**实时取自当前照片**（缩略图中心加权中位数饱和色）成为一圈环境光晕——照片色彩冷时自动改用当前**展厅灯**的辅助色，不会糊成一块。
- **翻页即换展**：上一张淡出、下一张携光入位，同屏最多两张，**任何输入都能打断**。
- **键盘表态（键位，不是摄像头）**：按 `S` 表示喜欢、`Delete` 或 `A` 表示跳过、`L` 表示锁定防误删。**按下的瞬间就写库**（单事务原子写），屏幕下方同时浮出一个 3 秒的提示条——反悔就**再按同一个键**撤销（回写空标记），不需要找撤销按钮。这三种标记与图库里的评分/私密/待删是同一套数据，改一处处处一致。
- 翻图仍可用 `←` / `→`，`Esc` 退出。私密过滤在凝视模式下同样生效。

## 11. ⌘K 检索与跳转

在任意页按 `Ctrl+K`（或点顶栏 🔍）唤出。用**一句人话**描述你要找的东西，面板把它拆成可点可改的「条件 chip」。

- **时间**：`去年` / `前年` / `今年` / `2021年` / `春天`（也认组合，如「去年秋天」）/ 月份 / `昨天` / `今天`。
- **人物**：直接写名字（前缀匹配）。名单来自人物馆的同一份聚合结果——**锁定态下不含只在私密照片里出现的人**。
- **地点**：省 / 市 / 大区名，取自库内实际出现的取值。
- **风格**：8 类场景标签的中文字面（人像 / 风光 / 夜景·星空 / 城市·建筑 / 微距·花卉 / 动物 / 美食 / 黑白）。
- **老能力保留**：标题、文件名、器材的包含匹配仍在，**零丢失**。
- **chip 可见即可纠**：点 chip 循环切换候选，`×` 移除。
- 动作行：`Enter` 执行检索；`C`「暂存为合集」是本轮**尚未上线**的占位项（灰显并有说明），不会被误当成可用功能。
- 全程**本机零网络**：词典是内置的，照片不出机器。

## 12. 展厅灯光（四灯与字阶）

顶栏 💡 打开灯菜单：

| 灯 | 名字 | 性格 |
|---|---|---|
| L1 | **夜展** | 默认。深炭底 + 翡翠主操作 + 琥珀金，最接近以往观感（**逐字节等于旧配色**，默认外观零回归） |
| L2 | **玉照** | 偏冷玉青，安静 |
| L3 | **素印** | 近灰阶，只有一处彩色点缀；适合挑选构图与影调 |
| L4 | **暮金** | 暖金，晚照感 |

- **换灯只换颜色**：表面、文字、描边、强调、阴影五组语义色随灯切换；**字号、间距、圆角、布局一律不变**——换灯不该挪版式。
- **「跟随空间」**：勾选后灯随你所在的页面自动切换（进了图库是一种光，进了修图台又是一种）；勾选状态下**手动切灯会立即解除跟随**，不会出现「点了没反应」的隐性模式。
- 切灯是**整帧重刷**并带一次缓动包络，不是局部跳色。

## 13. 隐私库

- 顶栏锁图标可对**指定照片**加私密标记并设口令；
- 浏览时可一键隐藏私密照片；
- **隐私一致**：私密照片不仅从浏览隐藏，也**不参与**相似去重、人物聚合、前厅候选、⌘K 人物词典等下游处理；
- 私密标记非破坏性（只隐藏不删除），口令只在本机校验。

## 14. 接入本地 AI 智能体（可选，**唯一仍需自备的服务**）

「AI 智能体」依赖本机运行的 [Ollama](https://ollama.com)：

1. 安装 Ollama 并拉取模型：`ollama pull qwen3.5:4b`；
2. 保持 Ollama 运行（默认监听 `127.0.0.1:11434`）；
3. 在修图页点「AI 智能体」，可输入修图目标（如「风光通透」「胶片感」）。

行为说明：

- 程序**只发送照片的客观测量值**，不发送照片本身；
- Ollama 未运行时自动回退本地规则推荐并标注来源；
- 除回环地址外不访问任何网络。

> **AI 分类与人脸功能不在此列**——它们不需要任何服务，见第 15 节。

## 15. 本地 AI 引擎（随包独立子进程，**不需要启动任何服务**）

三个 AI 能力各自对应一个**随包的可执行文件**，由程序按需拉起为**子进程**，通过标准输入/输出传递帧消息（`READY` / `REQ` / `RES` / `ERR`）。

**没有 HTTP 服务、没有端口监听、没有需要你先双击的 `.bat`。** 旧版要求的 8766（场景分类）与 8767（人脸）两个端口已彻底移除。

| 能力 | 引擎 | 包内位置 | 模型文件（与 exe 同目录） |
|---|---|---|---|
| AI 消除 | `inpaint.exe` | `3rdparty/lama/bin/` | `lama.onnx`（LaMa，Apache-2.0） |
| AI 分类 | `clipinfer.exe` | `3rdparty/clip/bin/` | `clip_vit_b32_img.onnx`（CLIP ViT-B/32 视觉塔）+ `prompts.bin`（8 类提示词矩阵） |
| 识别人物 / 智能聚类 | `faceinfer.exe` | `3rdparty/face/bin/` | `detection.onnx`（SCRFD-10GF 检测）+ `recognition.onnx`（ArcFace w600k_r50 识别） |

三个引擎都依赖 **ONNX Runtime 1.19.2**（MIT，随包 `onnxruntime.dll`）。`faceinfer.exe` 另需 `Qt6Core/Qt6Gui` 与 MinGW 运行库，以及 **JPEG 解码插件** `3rdparty/face/bin/imageformats/qjpeg.dll`——照片能不能被读进来，取决于这一小个文件在不在（见第 21 节）。

### 15.1 一次运算的时间花在哪里

- **首次拉起**要加载模型：人脸引擎实测 `READY` 约 **2.5 秒**（det+rec 两会话，合计约 191 MB），分类引擎实测在 **0.5–3.7 秒**摆动（视觉塔 351 MB）。程序给的等待预算分别为人脸 30 秒、分类 60 秒，足够容纳最慢的冷启动。
- 之后进程**常驻复用**，每张只需数百毫秒量级；一整库的批量运算成本主要在解码与读盘。
- 进程**保活、不因单张失败被杀**；协议不设「杀进程」码，取消只在批间/张间生效点被检查。

### 15.2 引擎读的是哪份数据

- **人脸识别读原图的绝对路径**，由子进程自己从磁盘读；程序不复制原片、不改写原片，也不把图像字节发给任何别的东西。
- **场景分类读库内缩略图**（分类只需要场景级判断，用缩略图换整库吞吐）。
- 两类都会**按 EXIF 方向摆正后再推理**——手机竖拍原图在库里存的是旋转过的像素，摆不平会让检测器大面积漏检（门禁里有一张 10 脸合影做回归夹具）。

### 15.3 出问题时你会看到什么

| 状态 | 你会看到 | 数据后果 |
|---|---|---|
| 引擎或模型文件缺失 | 点按钮弹出「**AI 引擎未就绪**（缺模型或引擎文件…）」，功能不启动 | 库完全不被触碰 |
| 引擎启动超时 / 崩溃 | 该轮如实报「中断（可能已部分写入）」，其余批次继续 | 已写入的部分保留，不写假标签 |
| 单张推理失败 | 该张被跳过（不标注），进度继续 | 该张保持未分类/未标注 |
| 你点取消 | 在下一次张间/片间检查点停下来，已完成部分照常写回 | 不丢已完成结果 |

> 包内**没有** `fetch_ai.ps1`（它属于源码树的准备脚本）。发布包用户遇到「引擎未就绪」，正确处置是：**重新完整解压**，或用包内 `MANIFEST.txt` 逐文件 `Get-FileHash` 比对，确认 `3rdparty/face/bin`、`3rdparty/clip/bin`、`3rdparty/lama/bin` 三个目录完整。自建/源码树用户才需要跑 `native/fetch_ai.ps1` 取模型。

## 18. 隐私与数据安全

- 全部功能**零云端**：无遥测、无账号、无联网上传。
- AI 分类与人脸推理**不经过任何 socket**，进程间只走标准输入/输出管道。三个引擎子进程**不发起任何网络请求**（`clipinfer.exe` 甚至不链接 Qt 网络模块）。
- 唯一仍会连接本机端口的是**可选的** Ollama 智能体（`127.0.0.1:11434`），且程序**只允许回环地址**，拒绝任何外部地址。
- 照片库是标准 SQLite 文件，可随时备份/迁移；
- 修图、美图、分类均「调整参数 → 导出副本」，**不修改原片**；故事相册不写库；凝视模式的表态写的是标记列，不动文件。

## 21. 故障排查

| 现象 | 处理 |
|---|---|
| 启动报「库打开失败」 | 检查 `LA_DB` 路径是否存在/被占用；或用环境变量指向有效库 |
| 前厅显示「今日无展 · 明日再会」 | **正常**——往年这一天确实没有可展出的照片（候选不足 3 张且同月/同季也没有）。这是诚实空态，不是加载失败 |

| 找不到原来的「选片」页 | 2.41.0 已退役该页（见第 19 节）。去重要用图库聚类条的「相似照片」 |
| 找不到原来的顶栏搜索框 | 已并入 **⌘K**（`Ctrl+K`）。老的关键词匹配仍在，只是换了入口 |
| 换了灯但感觉版式没变 | **符合设计**：灯只换颜色，不换字号/间距/布局 |
| 勾了「跟随空间」后手动切灯没反应 | 手动切灯会**自动解除跟随**，这是有意的；需要跟随时重新勾选 |
| 凝视模式键盘按了没反应 | 先把窗口点一下取得焦点；`S`/`Delete`/`A`/`L` 只在凝视模式生效，且每次按键都会浮出提示条（再按一次即撤销） |
| 足迹省份为 0 | 正常现象之一：照片无 GPS 或落在覆盖范围外（诚实留空） |
| **AI 分类 / 识别人物 / 智能聚类 提示「AI 引擎未就绪」** | **不需要启动服务**。请确认包解压完整：`3rdparty/face/bin/` 应有 `faceinfer.exe` + `detection.onnx` + `recognition.onnx` + `onnxruntime.dll` + `imageformats/qjpeg.dll`；`3rdparty/clip/bin/` 应有 `clipinfer.exe` + `clip_vit_b32_img.onnx` + `prompts.bin` + `onnxruntime.dll`。可用 `MANIFEST.txt` 逐个 `Get-FileHash` 比对，缺件就重新解压 |
| 文件明明都在，仍报「引擎未就绪」 | 两个方向：① 该机没装 Visual C++ 2015–2022 可再分发库（`onnxruntime.dll` 的依赖，见第 19 节）；② `3rdparty/face/bin/imageformats/` 被杀软或手工移走——此时**JPEG 一律读不进**，而 PNG 仍正常。表现就是「只有 JPEG 照片的人脸功能失败」 |
| 竖拍的手机照片检不到脸 | 已按 EXIF 方向摆正后再检测。若你的库是在**更旧版本**上做的标注，建议对这批照片重跑一次「识别人物」 |
| AI 消除提示「模型未就绪」 | 确认 `3rdparty/lama/bin/` 内执行器与模型文件完整（见第 20 节槽位说明）；缺失时相应功能诚实挂起，其余不受影响 |
| AI 消除点「应用」后显示处理中 | 正常——本地模型推理需要数秒，界面可继续操作，也可取消 |
| 第一次点 AI 分类比后面慢很多 | 正常——首帧要加载 351 MB 视觉塔（见 15.1） |
| 一整批跑完提示「中断（可能已部分写入）」 | 说明这一轮**不是干净跑完**（被取消，或有张失败）。已写入的标注是真实的，重跑只会补齐未标注的照片 |
| 智能聚类后人物分组不理想 | 先把分错的照片改名归并；两遍精炼倾向于宁可多分不漏合 |
| 高分屏下界面发糊 | 确认未强制 `QT_SCALE_FACTOR`；程序按系统缩放渲染 |
| 故事条分组不符合预期 | 「地点 + 时间窗口」启发式视图，非缺陷（见 5.2） |
